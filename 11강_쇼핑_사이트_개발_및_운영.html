1 강의 개요와 시작 상태 확인

🎯 학습목표
  • 컴포넌트에 넘기는 값(props)에 타입을 붙일 수 있다.
  • 배열 데이터를 map으로 화면에 그릴 수 있다.
  • 데이터 파일을 .js, .json, .ts 중 무엇으로 둘지 판단할 수 있다.
  • as const, Omit 같은 TypeScript 문법으로 타입을 설계할 수 있다.
  • Context API로 여러 화면이 함께 쓰는 상태를 만들 수 있다.
  • 입력 폼의 값을 상태로 관리하고, 검사한 뒤 Context에 저장할 수 있다.
  • 한 Context가 다른 Context를 쓸 때 Provider를 감싸는 순서를 정할 수 있다.

📖 시작 상태

Vite로 만든 React + TypeScript 프로젝트에 react-router-dom을 설치한 상태에서 시작합니다.

💡 예제 — App.tsx
src/App.tsx 
import { BrowserRouter, Route, Routes } from 'react-router-dom';
import './App.css'
import Header from './layouts/Header';
import ProductList from './products/ProductList';

function App() {

  return (
    <BrowserRouter>
      <Header />
      <main>
        <Routes>
          <Route path='/' element={<ProductList />} />
        </Routes>
      </main>
    </BrowserRouter>
  )
}

export default App;

2 상품 카드와 상품 목록 컴포넌트

🎯 학습목표
  • props에 interface로 타입을 붙일 수 있다.
  • 배열 데이터를 map과 key로 화면에 그릴 수 있다.

상품 하나를 그리는 ProductCard와, 여러 상품을 반복해서 그리는 ProductList로 나눕니다.

💡 예제 — 상품 카드
src/products/ProductCard.tsx 
import type { ProductProp } from './ProductList';

interface ProductCardProps {
  product: ProductProp;
}

const ProductCard = ({ product }: ProductCardProps) => {

  return(
    <div className="card">
      <span>{product.category}</span>
      <h3>{product.pName}</h3>
      <p>{product.price.toLocaleString()}원</p>
    </div>
  )
}

export default ProductCard;
  • ProductCardProps는 이 컴포넌트가 받는 값의 규칙입니다.
  • toLocaleString()은 25000을 25,000처럼 천 단위 쉼표를 붙여 줍니다.
💡 예제 — 상품 목록
src/products/ProductList.tsx 
import ProductCard from './ProductCard';

export interface ProductProp {
  id: number;
  pName: string;
  category: string;
  price: number;
}

const products: ProductProp[] = [ /* 상품 데이터 */ ];

const ProductList = () => {

  return(
    <div className='product-list'>
      {products.map((product) => (
        <ProductCard
          key={product.id}
          product={product}
        />
      ))}
    </div>
  )
}

export default ProductList;

📖 짚고 넘어갈 점

  • ProductCard에서 타입을 가져다 쓰므로 interface 앞에 export 가 꼭 필요합니다.
  • map으로 그리는 요소에는 key 를 붙입니다. React가 어떤 항목이 바뀌었는지 구분하는 데 씁니다.
  • key에는 배열 순서(index)보다 변하지 않는 고유 값(id) 을 쓰는 것이 좋습니다.

3 데이터 파일 분리 (.js → .ts)

🎯 학습목표
  • 데이터 파일을 .js · .json · .ts 중 무엇으로 둘지 판단할 수 있다.
  • as 타입 단언이 검사를 끄는 것에 가깝다는 점을 이해한다.

상품 데이터를 컴포넌트 밖 src/datas/ 폴더로 옮깁니다. 이때 파일 형식을 무엇으로 할지 고민해 봅니다.

📖 .json vs .ts 비교

.ts.json
타입 검사항목을 빠뜨리거나 잘못 적으면 바로 오류값만 보고 타입을 추측, 오타를 못 잡음
주석, 마지막 쉼표가능불가능
어울리는 상황코드 안에서 직접 가져다 쓸 때fetch로 서버처럼 불러올 때 (public/products.json)

TypeScript 프로젝트에서 코드로 직접 가져다 쓴다면 .ts 가 유리합니다.

💡 정리 .json을 가져와서 as ProductProp[]로 타입을 붙이면 오류는 사라지지만, 실제로 데이터가 규칙에 맞는지는 검사하지 않습니다. 검사를 끄는 것에 가깝습니다.

4 타입 파일 분리

🎯 학습목표
  • 여러 파일이 쓰는 타입을 별도 파일로 분리해 의존 관계를 정리할 수 있다.
  • import type의 의미를 설명할 수 있다.

지금은 상품 타입이 ProductList.tsx 안에 있어서, 데이터 파일과 카드 컴포넌트가 목록 컴포넌트에 의존하게 됩니다.

ProductCard ──→ ProductList (타입 때문에) products.ts ──→ ProductList (타입 때문에)

타입을 별도 파일로 빼면 모두가 한 곳만 바라보게 됩니다.

ProductCard ──→ types/product.ts ProductList ──→ types/product.ts products.ts ──→ types/product.ts

import type을 쓰면 타입만 가져온다는 뜻이 분명해지고, 빌드 결과에서도 빠집니다.

import type { Product } from '../types/product';

5 확장을 고려한 타입 설계

🎯 학습목표
  • 역할에 맞는 타입 이름을 지을 수 있다.
  • as const와 typeof 배열[number]로 값과 타입을 한 곳에서 관리할 수 있다.
  • Omit으로 등록용 파생 타입을 만들 수 있다.

앞으로 상품 등록 기능을 붙인다고 생각하고 타입을 다듬습니다.

💡 예제 — product.ts
src/types/product.ts 
export const CATEGORIES = ['마우스', '키보드', '모니터', '주변기기', '음향'] as const;

export type Category = typeof CATEGORIES[number];

export interface Product {
  id: number;
  pName: string;
  category: Category;
  price: number;
  desc: string;
}

// 상품 등록 시 입력받는 값 (id는 저장할 때 생성)
export type NewProduct = Omit<Product, 'id'>;

📖 ① 이름 바꾸기: ProductProp → Product

Prop은 컴포넌트에 넘기는 값처럼 보이지만, 이 타입은 상품 데이터 자체입니다. 이름이 역할을 정확히 말해 주도록 바꿉니다.

📖 ② 카테고리 목록: as const

const CATEGORIES = ['마우스', '키보드'];           // string[]
const CATEGORIES = ['마우스', '키보드'] as const;  // readonly ['마우스', '키보드']
  • as const를 붙이면 값 하나하나가 그대로 타입이 됩니다.
  • typeof CATEGORIES[number]는 배열 안의 값들을 모아 '마우스' | '키보드' | ... 타입을 만듭니다.
  • 배열은 화면의 선택 목록(select)에, 타입은 검사에 함께 쓸 수 있어 한 곳만 고치면 됩니다.
  • 목록에 없는 카테고리를 적으면 바로 오류가 납니다.

📖 ③ 등록용 타입: Omit

사용자가 상품을 등록할 때는 번호(id)를 입력하지 않습니다. 번호는 저장할 때 만들어집니다.

type NewProduct = Omit<Product, 'id'>;
// { pName: string; category: Category; price: number; desc: string; }

Product를 고치면 NewProduct도 자동으로 따라 바뀝니다.

6 Context로 상품 상태 공유

🎯 학습목표
  • 여러 화면이 함께 쓰는 상태가 왜 필요한지 설명할 수 있다.
  • Context · Provider · 커스텀 훅을 파일로 나눠 상품 상태를 공유할 수 있다.
  • 이전 값을 받는 setState와 새 배열로 불변성을 지킬 수 있다.

📖 왜 필요할까?

지금 상품 목록은 파일에서 가져와 읽기만 하는 고정된 배열입니다. 상품 등록 화면에서 새 상품을 만들어도 담아 둘 곳이 없고, 목록 화면에 반영할 방법도 없습니다.

[상품 등록 화면] ──추가──→ ??? ←──읽기── [상품 목록 화면]

여러 화면이 같은 데이터를 함께 쓰려면 공용 저장소가 필요합니다. React의 Context API를 사용합니다.

💡 예제 — ① Context와 꺼내 쓰는 함수 만들기
src/contexts/ProductContext.ts 
import { createContext, useContext } from 'react';
import type { NewProduct, Product } from '../types/product';

interface ProductContextValue {
  products: Product[];
  addProduct: (product: NewProduct) => void;
}

export const ProductContext = createContext<ProductContextValue | null>(null);

export const useProducts = () => {
  const context = useContext(ProductContext);
  if (!context) {
    throw new Error('useProducts는 ProductProvider 안에서 사용해야 합니다.');
  }
  return context;
}
  • 처음 값을 null로 두고, useProducts 안에서 null인지 확인합니다.
  • 덕분에 사용하는 쪽에서는 매번 null 검사를 하지 않아도 됩니다.
  • Provider 밖에서 실수로 쓰면 어디가 잘못됐는지 알려 주는 오류가 납니다.
💡 예제 — 데이터 파일 정리 (initialProducts)
src/datas/products.ts 
import type { Product } from '../types/product';

// 상품 목록의 처음 값으로만 쓰므로 이름을 initialProducts로 바꿉니다.
export const initialProducts: Product[] = [
  { id: 1, pName: "무선 마우스", category: "마우스", price: 25000, desc: "조용한 클릭음의 2.4GHz 무선 마우스" },
  { id: 2, pName: "기계식 키보드", category: "키보드", price: 89000, desc: "청축 스위치, RGB 백라이트" },
  // ...
];
  • 4단계에서 만든 Product 타입을 가져와 붙입니다. category가 CATEGORIES에 없는 값이면 바로 오류가 납니다.
  • 이제 이 배열은 Provider의 처음 값으로만 쓰므로 이름을 initialProducts로 바꿉니다.
💡 예제 — ② 저장소 컴포넌트(Provider) 만들기
src/contexts/ProductProvider.tsx 
import { useState, type ReactNode } from 'react';
import { ProductContext } from './ProductContext';
import { initialProducts } from '../datas/products';
import type { NewProduct, Product } from '../types/product';

const ProductProvider = ({ children }: { children: ReactNode }) => {
  const [products, setProducts] = useState<Product[]>(initialProducts);

  const addProduct = (product: NewProduct) => {
    setProducts((prev) => {
      const nextId = Math.max(0, ...prev.map((p) => p.id)) + 1;
      return [...prev, { ...product, id: nextId }];
    });
  }

  return(
    <ProductContext.Provider value={{ products, addProduct }}>
      {children}
    </ProductContext.Provider>
  )
}

export default ProductProvider;
  • 데이터 파일의 상품은 처음 값(initialProducts) 으로만 씁니다. 이름도 그 역할에 맞게 바꿉니다.
  • addProduct는 NewProduct(id 없음)를 받아서, 가장 큰 id + 1로 번호를 붙여 저장합니다.
  • setProducts((prev) => ...)처럼 이전 값을 받아 계산하면 여러 번 연달아 호출해도 안전합니다.
  • 기존 배열을 고치지 않고 [...prev, 새상품]으로 새 배열을 만들어야 React가 변화를 알아챕니다.
💡 왜 파일을 두 개로 나눴나요? Vite의 빠른 새로고침(Fast Refresh)은 컴포넌트만 내보내는 파일에서 가장 잘 동작합니다. 컴포넌트(ProductProvider)와 컴포넌트가 아닌 것(ProductContext, useProducts)을 나눠 두면 저장할 때 화면 상태가 유지됩니다.

💡 예제 — ⑤ 상세 화면에서 꺼내 쓰기 (상품 상세 보기)
src/products/ProductDetail.tsx 
import { Link, useParams } from 'react-router-dom';
import { useProducts } from '../contexts/ProductContext';

const ProductDetail = () => {
  const { id } = useParams<{ id: string }>();
  const { products } = useProducts();

  // 해당 id와 일치하는 상품 찾기
  const product = products.find((item) => item.id === Number(id));

  if (!product) {
    return (
      <section className="product-detail">
        <h2>상품을 찾을 수 없습니다.</h2>
        <Link to="/">상품 목록으로 돌아가기</Link>
      </section>
    );
  }

  return (
    <article className="product-detail">
      <Link to="/" className="product-detail__back">← 상품 목록</Link>
      <span className="product-detail__category">{product.category}</span>
      <h2>{product.pName}</h2>

import { CATEGORIES, type Category } from '../types/product';

// 입력창의 값은 항상 문자열이므로 가격도 문자열로 받고, 등록할 때 숫자로 바꿉니다.
interface ProductForm {
  pName: string;
  category: Category;
  price: string;
  desc: string;
}

const initialForm: ProductForm = {
  pName: '',
  category: CATEGORIES[0],
  price: '',
  desc: '',

const AddProduct = () => {
  const { addProduct } = useProducts();
  const navigate = useNavigate();

  const [form, setForm] = useState<ProductForm>(initialForm);
  const [error, setError] = useState('');

  const { pName, category, price, desc } = form;

  // 입력창의 name과 form의 키를 같게 두어서 핸들러 하나로 모든 입력을 처리합니다.
  const handleInputChange = (
    e: ChangeEvent<HTMLInputElement | HTMLTextAreaElement | HTMLSelectElement>
  ) => {
    const { name, value } = e.target;

    e.preventDefault();

  }

  const handleCancel = () => {
    navigate('/');
  }

  return(
    <div className="add-product">

        <div>

          <label htmlFor="category">카테고리</label>

            id="category"
            name="category"
            value={category}
            onChange={handleInputChange}
          >

              <option key={item} value={item}>{item}</option>
            ))}
          </select>
        </div>

  • initialForm을 컴포넌트 밖에 두면 렌더링할 때마다 새로 만들지 않습니다. 카테고리 처음 값은 CATEGORIES[0]으로 둡니다.
  • 핸들러 하나: [name]: value는 변수 값을 키로 쓰는 문법입니다. 입력창의 name 속성을 ProductForm의 키와 똑같이 적어야 동작합니다.
  • input, textarea, select에서 함께 쓰므로 이벤트 타입을 |로 묶습니다.
  • e.preventDefault()로 제출 시 새로고침을 막습니다. 새로고침되면 메모리에 있던 상품이 모두 사라집니다.
  • Number('')는 0, Number('abc')는 NaN이므로 비어 있는지와 정수인지를 함께 확인하고, 걸리면 return으로 바로 끝냅니다.
  • addProduct에는 NewProduct 타입을 넘겨야 하므로, 가격을 문자열 그대로 넘기면 TypeScript가 오류를 알려 줍니다.
  • 취소 버튼은 type="button"으로 둡니다. form 안의 버튼은 기본이 submit이라 적지 않으면 취소를 눌러도 등록이 실행됩니다.
💡 정리 입력창 값은 항상 문자열이라 폼 전용 타입 ProductForm에서는 price를 string으로 두고, 등록할 때 Number(price)로 바꿔 NewProduct 모양으로 addProduct에 넘깁니다. 카테고리 선택 목록은 CATEGORIES를 그대로 map해서 만들므로, 카테고리가 늘어나도 types/product.ts 한 곳만 고치면 됩니다.

7 장바구니

🎯 학습목표
  • 장바구니에 상품 번호와 수량만 저장하는 이유를 설명하고 CartItem, CartLine 타입을 만들 수 있다.
  • 상품과 같은 구조로 CartContext, CartProvider, useCart를 만들어 장바구니 상태를 공유할 수 있다.
  • 담기 · 수량 변경 · 삭제 · 전체 비우기 기능과 합계 수량 · 금액 계산을 구현할 수 있다.
  • 다른 Context를 쓰는 Provider를 감싸는 순서를 정할 수 있다.
  • 장바구니 화면 · 상품 카드 · 상세 · 헤더에서 useCart()로 같은 장바구니 상태를 꺼내 쓸 수 있다.

📖 왜 장바구니도 Context일까?

장바구니도 여러 화면이 함께 쓰는 데이터입니다. 카드와 상세에서 담고, 헤더와 장바구니 화면에서 읽습니다.

[상품 카드] ──담기──┐ [상품 상세] ──담기──┼──→ ??? ←──읽기── [헤더 개수] [장바구니 화면]

그래서 상품의 ProductContext와 같은 방식으로 CartContext를 만듭니다.

📖 무엇을 저장할까?

상품 전체 저장번호와 수량만 저장
저장 모양{ id, pName, price, ..., quantity }{ productId, quantity }
상품 가격이 바뀌면장바구니에는 예전 가격이 남음상품 목록에서 찾으므로 바뀐 가격이 나옴
같은 정보두 곳에 있음한 곳(상품 목록)에만 있음

같은 정보를 두 곳에 두면 한쪽만 바뀌는 문제가 생기므로 번호와 수량만 저장합니다.

💡 예제 — ① 장바구니 타입
src/types/cart.ts 
import type { Product } from './product';

// 장바구니에는 상품 id와 수량만 저장하고, 상품 정보는 상품 목록에서 찾아 씁니다.
export interface CartItem {
  productId: number;
  quantity: number;
}

// 화면에 보여줄 때 상품 정보와 합친 형태
export interface CartLine {
  product: Product;
  quantity: number;
}
💡 정리 CartItem은 저장용(상품 번호 + 수량), CartLine은 화면 표시용(상품 정보 + 수량)입니다. 장바구니에 상품 정보 전체를 복사해 두지 않고 번호만 저장하므로, 상품 가격이나 이름이 바뀌어도 장바구니에는 항상 최신 정보가 나옵니다.
💡 예제 — ② 장바구니 Context와 꺼내 쓰는 함수
src/contexts/CartContext.ts 
import { createContext, useContext } from 'react';
import type { CartLine } from '../types/cart';

interface CartContextValue {
  cartLines: CartLine[];
  totalQuantity: number;
  totalPrice: number;
  addToCart: (productId: number, quantity?: number) => void;
  updateQuantity: (productId: number, quantity: number) => void;
  removeFromCart: (productId: number) => void;
  clearCart: () => void;
}

export const CartContext = createContext<CartContextValue | null>(null);

export const useCart = () => {
  const context = useContext(CartContext);
  if (!context) {
    throw new Error('useCart는 CartProvider 안에서 사용해야 합니다.');
  }
  return context;
}
💡 정리 상품의 ProductContext.ts와 같은 구조입니다. quantity?: number처럼 ?를 붙이면 생략할 수 있는 매개변수가 되어 addToCart(1)로도, addToCart(1, 3)으로도 호출할 수 있습니다. 화면에는 CartItem이 아니라 상품 정보가 합쳐진 CartLine[]을 넘겨서 각 화면이 상품을 다시 찾지 않아도 되게 합니다.
💡 예제 — ③ 장바구니 저장소 컴포넌트(Provider)
src/contexts/CartProvider.tsx 
import { useState, type ReactNode } from 'react';
import { CartContext } from './CartContext';
import { useProducts } from './ProductContext';
import type { CartItem, CartLine } from '../types/cart';

// 상품 목록이 필요하므로 ProductProvider 안쪽에 두어야 합니다.
const CartProvider = ({ children }: { children: ReactNode }) => {
  const { products } = useProducts();
  const [items, setItems] = useState<CartItem[]>([]);

  // 이미 담긴 상품이면 수량만 늘리고, 없으면 새로 추가합니다.
  const addToCart = (productId: number, quantity = 1) => {
    setItems((prev) => {
      const exists = prev.some((item) => item.productId === productId);
      if (exists) {
        return prev.map((item) =>
          item.productId === productId
            ? { ...item, quantity: item.quantity + quantity }
            : item
        );
      }
      return [...prev, { productId, quantity }];
    });
  }

  // 수량은 1개 이상만 허용합니다. 빼려면 removeFromCart를 사용합니다.
  const updateQuantity = (productId: number, quantity: number) => {
    if (quantity < 1) return;
    setItems((prev) =>
      prev.map((item) =>
        item.productId === productId ? { ...item, quantity } : item
      )
    );
  }

  const removeFromCart = (productId: number) => {
    setItems((prev) => prev.filter((item) => item.productId !== productId));
  }

  const clearCart = () => {
    setItems([]);
  }

  // 저장된 id로 상품 정보를 찾아 붙입니다. 찾을 수 없는 상품은 제외합니다.
  const cartLines: CartLine[] = items.flatMap((item) => {
    const product = products.find((p) => p.id === item.productId);
    return product ? [{ product, quantity: item.quantity }] : [];
  });

  const totalQuantity = cartLines.reduce((sum, line) => sum + line.quantity, 0);
  const totalPrice = cartLines.reduce(
    (sum, line) => sum + line.product.price * line.quantity,
    0
  );

  return(
    <CartContext.Provider
      value={{
        cartLines,
        totalQuantity,
        totalPrice,
        addToCart,
        updateQuantity,
        removeFromCart,
        clearCart,
      }}
    >
      {children}
    </CartContext.Provider>
  )
}

export default CartProvider;
  • 담기: some으로 이미 담긴 상품인지 확인해서, 있으면 줄을 하나 더 만들지 않고 수량만 늘립니다. quantity = 1은 기본값이라 addToCart(상품번호)만 부르면 1개가 담깁니다.
  • map으로 바꿀 항목만 { ...item, quantity: ... } 새 객체로 만들고, 나머지는 그대로 둡니다.
  • 수량 변경: 1보다 작으면 무시해서 0개짜리 상품이 남지 않게 합니다. 빼기는 filter로 해당 상품만 제외한 새 배열을 만듭니다.
  • 계산할 수 있는 값은 상태로 두지 않기: 총 수량 · 총 금액을 useState로 따로 두면 담을 때마다 함께 고쳐야 하고, 하나라도 빠뜨리면 숫자가 틀어집니다. items에서 매번 계산하면 항상 맞는 값이 나옵니다.
  • flatMap은 찾은 상품은 [값], 못 찾은 상품은 []를 돌려받아 한 겹 펼치므로 변환과 걸러내기를 한 번에 합니다. reduce의 마지막 0은 시작 값입니다.
💡 참고 map 후 filter로 걸러도 됩니다. 다만 TypeScript 5.4 이하에서는 undefined가 빠졌다는 것을 알아채지 못해 타입이 (CartLine | undefined)[]로 남습니다(5.5부터는 자동으로 좁혀짐). flatMap은 버전과 관계없이 CartLine[]이 됩니다.

            <Routes>
              <Route path='/' element={<ProductList />} />
              <Route path='/products/new' element={<AddProduct />} />
              <Route path='/products/:id' element={<ProductDetail />} />
              <Route path='/cart' element={<Cart />} />
            </Routes>
          </main>
        </BrowserRouter>
      </CartProvider>
    </ProductProvider>
  )
}

export default App;

CartProvider는 안에서 useProducts()를 쓰므로 ProductProvider 안쪽에 있어야 합니다. 순서를 거꾸로 하면 useProducts는 ProductProvider 안에서 사용해야 합니다. 오류가 납니다. 6단원에서 넣어 둔 오류 메시지 덕분에 원인을 바로 알 수 있습니다.

ProductProvider ← products └── CartProvider ← useProducts()로 products를 읽음 └── 화면들 ← useProducts(), useCart() 둘 다 사용 가능
💡 예제 — ⑤ 장바구니 화면
src/cart/Cart.tsx 
import { Link } from 'react-router-dom';
import { useCart } from '../contexts/CartContext';

const Cart = () => {
  const {
    cartLines,
    totalQuantity,
    totalPrice,
    updateQuantity,
    removeFromCart,
    clearCart,
  } = useCart();

  if (cartLines.length === 0) {
    return (
      <section className="cart">
        <h2>장바구니</h2>
        <p className="cart__empty">장바구니가 비어 있습니다.</p>
        <Link to="/" className="cart__link">상품 보러 가기</Link>
      </section>
    );
  }

  const handleClear = () => {
    if (confirm('장바구니를 모두 비울까요?')) {
      clearCart();
    }
  }

  return (
    <section className="cart">
      <h2>장바구니</h2>
      <ul className="cart__list">
        {cartLines.map(({ product, quantity }) => (
          <li key={product.id} className="cart__item">
            <div className="cart__info">
              <span className="cart__category">{product.category}</span>
              <Link to={`/products/${product.id}`}>{product.pName}</Link>
              <span>{product.price.toLocaleString()}원</span>
            </div>
            <div className="cart__quantity">
              <button
                type="button"
                onClick={() => updateQuantity(product.id, quantity - 1)}
                disabled={quantity <= 1}
              >
                −
              </button>
              <span>{quantity}</span>
              <button
                type="button"
                onClick={() => updateQuantity(product.id, quantity + 1)}
              >
                +
              </button>
            </div>
            <strong className="cart__subtotal">
              {(product.price * quantity).toLocaleString()}원
            </strong>
            <button
              type="button"
              className="cart__remove"
              onClick={() => removeFromCart(product.id)}
            >
              삭제
            </button>
          </li>
        ))}
      </ul>
      <div className="cart__summary">
        <span>총 {totalQuantity}개</span>
        <strong>{totalPrice.toLocaleString()}원</strong>
      </div>
      <div className="cart__buttons">
        <button type="button" onClick={handleClear}>전체 비우기</button>
        <Link to="/" className="cart__link">쇼핑 계속하기</Link>
      </div>
    </section>
  );
}

export default Cart;
  • 비어 있을 때를 먼저 처리하고 return 합니다. 아래 코드는 상품이 있다고 생각하고 쓸 수 있습니다.
  • map(({ product, quantity }) => ...)처럼 매개변수 자리에서 바로 구조 분해할 수 있습니다.
  • − 버튼은 수량이 1이면 disabled로 막습니다. Provider에서도 막아 두었지만 누를 수 없다는 것을 화면으로 보여 주는 것이 더 친절합니다.
  • 소계(가격 × 수량)도 저장하지 않고 화면에서 바로 계산합니다.
  • 전체 비우기는 되돌릴 수 없으므로 confirm으로 한 번 더 묻습니다.

📖 ⑥ 담기 버튼과 헤더 개수 표시

어느 컴포넌트든 useCart()만 부르면 장바구니를 쓸 수 있습니다.

💡 예제 — ⑥ 상품 카드에 담기 버튼
src/products/ProductCard.tsx 
import { Link } from 'react-router-dom';
import { useCart } from '../contexts/CartContext';
import type { Product } from '../types/product';

interface ProductCardProps {
  product: Product;
}

const ProductCard = ({ product }: ProductCardProps) => {

  return(
    <div className="card">
      <span>{product.category}</span>
      {/* 상품명을 누르면 상세 화면으로 이동합니다. */}

    </div>

💡 주의 카드 전체를 Link로 감싸면 그 안에 담기 버튼이 들어가 링크 안에 버튼이 있는 잘못된 구조가 됩니다. 그래서 상품명(h3)에만 Link를 겁니다.
💡 예제 — ⑥ 상품 상세에 담기 버튼
src/products/ProductDetail.tsx 
import { Link, useParams } from 'react-router-dom';
import { useProducts } from '../contexts/ProductContext';
import { useCart } from '../contexts/CartContext';

const ProductDetail = () => {
  const { id } = useParams<{ id: string }>();
  const { products } = useProducts();
  const { addToCart } = useCart();

  // 해당 id와 일치하는 상품 찾기
  const product = products.find((item) => item.id === Number(id));

  if (!product) {
    return (
      <section className="product-detail">
        <h2>상품을 찾을 수 없습니다.</h2>
        <Link to="/">상품 목록으로 돌아가기</Link>
      </section>
    );
  }

  return (
    <article className="product-detail">
      <Link to="/" className="product-detail__back">← 상품 목록</Link>
      <span className="product-detail__category">{product.category}</span>
      <h2>{product.pName}</h2>
      <p className="product-detail__price">{product.price.toLocaleString()}원</p>
      <p className="product-detail__desc">{product.desc}</p>
      <button
        type="button"
        className="product-detail__cart"
        onClick={() => {
          addToCart(product.id);
          alert('장바구니에 담았습니다.');
        }}
      >
        장바구니 담기
      </button>
    </article>
  );
}

export default ProductDetail;
💡 주의 useCart()도 Hook이므로 if (!product) return 위에서 불러야 합니다. Hook은 조건문이나 return 뒤에서 부를 수 없습니다.

📖 생각해 볼 점 — 새로고침하면 장바구니가 비워집니다

장바구니도 상품 목록처럼 메모리에만 있습니다. localStorage에 저장하면 새로고침 후에도 남길 수 있습니다.

const [items, setItems] = useState<CartItem[]>(() => {
  const saved = localStorage.getItem('cart');
  return saved ? JSON.parse(saved) : [];
});

useEffect(() => {
  localStorage.setItem('cart', JSON.stringify(items));
}, [items]);
  • useState(() => ...)처럼 함수를 넘기면 처음 한 번만 실행됩니다. (useEffect도 import해야 합니다.)
  • 이때 상품 목록은 저장되지 않으므로 직접 등록한 상품은 새로고침 후 사라집니다. ③에서 찾을 수 없는 상품을 제외하도록 만들어 두었기 때문에 화면이 깨지지 않습니다.

📖 생각해 볼 점 — 담았다는 것을 알리는 방법

상세 화면에서는 alert로 알리지만, alert은 확인을 누를 때까지 화면 전체를 멈춥니다. 여러 개를 연달아 담는 목록 화면에는 넣지 않았고, 헤더 숫자가 바뀌는 것으로 대신합니다. 잠깐 보였다 사라지는 안내 메시지(토스트)로 바꾸는 방법도 있습니다.

📖 정리

  1. 장바구니에는 상품 전체가 아니라 번호와 수량만 저장하고, 상품 정보는 목록에서 찾는다.
  2. 이미 담긴 상품은 some으로 확인해서 새 줄 대신 수량만 늘린다.
  3. 총 수량, 총 금액, 소계처럼 계산할 수 있는 값은 상태로 두지 않는다.
  4. 다른 Context를 쓰는 Provider는 그 Context의 Provider 안쪽에 둔다.
  5. 같은 Context를 보는 컴포넌트들은 서로 몰라도 함께 바뀐다.
