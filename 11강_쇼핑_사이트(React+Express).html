쇼핑 사이트 (React + Express)

10강에서 만든 React 쇼핑 사이트를 Express + PostgreSQL 서버와 연결합니다. 상품과 회원 데이터를 브라우저 메모리 대신 DB에서 불러오고 저장합니다.

1 Express 서버(API)

🎯 학습목표
  • Express와 nodemon을 설치하고 npm start로 서버를 실행할 수 있다.
  • pg 라이브러리로 PostgreSQL에 연결할 수 있다.
  • 상품 목록 · 단건 조회 · 등록 · 수정 · 삭제 API를 만들 수 있다.
  • 회원 목록 · 회원 가입 · 로그인 API를 만들 수 있다.
💡 예제 — 1. express 설치
터미널 
mkdir server
cd server
npm init -y
npm install express
  • React 프로젝트와 따로 server 폴더를 만들어 서버 코드를 둡니다.
  • npm init -y는 기본값으로 package.json을 만듭니다.

📖 package.json에 "type": "module" 추가

{
  "name": "server",
  "version": "1.0.0",
  "main": "index.js",
  "type": "module"
}

"type": "module"을 넣어야 import express from 'express'처럼 import 문법과 파일 맨 위의 await를 쓸 수 있습니다. 넣지 않으면 Node는 예전 방식(const express = require('express'))으로 읽기 때문에 import에서 오류가 납니다.

💡 예제 — 2. 가장 기본적인 Express 서버
server/index.js 
import express from 'express';

// Express 객체 생성
const app = express();

// 라우트 설정
app.get('/', (req, res) => {
  // 클라이언트에게 응답 보내기
  res.send('<h2>Hello, World!</h2>');
});

// 서버 실행
const PORT = 8000;
app.listen(PORT, () => {
  console.log(`서버 실행중... http://localhost:${PORT}`);
});

💡 예제 — 5. PostgreSQL 연결 — ① 계정 · DB 생성 (postgres 계정 / postgres DB)
pgAdmin 4 — Query Tool 
-- postgres(계정), postgres(DB) 접속

-- 계정 생성: 이미 존재하는 계정이면 생략하고 DB 생성 문장만 선택해 실행
CREATE USER jsuser WITH PASSWORD 'pwjs';

-- DB 생성 (jsuser를 소유자로 지정)
CREATE DATABASE tsdb OWNER jsuser;
  • 관리자 계정(postgres)으로 postgres DB에 접속해서 실행합니다.
  • 한 줄씩 블록으로 선택한 뒤 실행(F5)합니다. 여러 문장을 한꺼번에 실행하면 CREATE DATABASE에서 cannot run inside a transaction block 오류가 날 수 있습니다.
  • 수업용 계정 jsuser를 만들고, tsdb DB의 소유자로 지정합니다. 소유자는 그 DB 안에서 테이블을 만들고 고칠 수 있습니다.
💡 참고 — jsuser가 이미 있는 경우 앞 강의에서 jsuser 계정을 이미 만들었다면 CREATE USER는 role "jsuser" already exists 오류가 납니다. 계정은 PostgreSQL 서버 전체에서 하나만 있으면 되므로, 이때는 CREATE DATABASE tsdb OWNER jsuser; 한 줄만 선택해 실행해서 기존 계정을 새 DB의 소유자로 지정합니다. 비밀번호도 앞에서 정한 pwjs를 그대로 씁니다.
💡 예제 — 5. PostgreSQL 연결 — ② 상품 테이블 · 초기 데이터 (jsuser 계정 / tsdb DB)
pgAdmin 4 — Query Tool 
CREATE TABLE products (
  id          SERIAL PRIMARY KEY,
  p_name      VARCHAR(100) NOT NULL,
  category    VARCHAR(20)  NOT NULL
              CHECK (category IN ('마우스', '키보드', '모니터', '주변기기')),
  price       INTEGER      NOT NULL CHECK (price >= 0),
  description TEXT         NOT NULL DEFAULT '',
  created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

-- 초기 데이터
INSERT INTO products (p_name, category, price, description) VALUES
  ('무선 마우스',        '마우스',   25000,  '조용한 클릭음의 2.4GHz 무선 마우스'),
  ('기계식 키보드',      '키보드',   89000,  '청축 스위치, RGB 백라이트'),
  ('27인치 모니터',      '모니터',   279000, 'QHD 해상도, 165Hz 주사율'),
  ('USB-C 허브',         '주변기기', 39000,  'HDMI·USB 3.0·SD 카드 지원 7in1'),
  ('웹캠 FHD',           '주변기기', 45000,  '1080p 30fps, 자동 초점');
  • jsuser 계정으로 tsdb DB에 접속해서 실행합니다. 그래야 테이블의 소유자가 jsuser가 됩니다.
  • SERIAL은 번호를 자동으로 1씩 증가시킵니다. 등록할 때 id를 넣지 않아도 됩니다.
  • CHECK는 들어갈 수 있는 값을 DB에서 한 번 더 막습니다. 카테고리는 목록에 있는 값만, 가격은 0 이상만 저장됩니다.
  • DEFAULT는 값을 넣지 않았을 때의 기본값입니다. created_at에는 저장한 시각(NOW())이 자동으로 들어갑니다.
  • PostgreSQL은 이름을 소문자로 다루므로 컬럼 이름은 p_name처럼 소문자와 밑줄로 짓습니다.
💡 예제 — 5. PostgreSQL 연결 — ③ 회원 테이블 · 초기 데이터 (jsuser 계정 / tsdb DB)
pgAdmin 4 — Query Tool 
CREATE TABLE users (
  id          SERIAL PRIMARY KEY,
  username    VARCHAR(16)  NOT NULL UNIQUE,
  password    VARCHAR(255) NOT NULL,
  name        VARCHAR(50)  NOT NULL,
  email       VARCHAR(100) NOT NULL UNIQUE,
  role        VARCHAR(10)  NOT NULL DEFAULT 'user'
              CHECK (role IN ('user', 'admin')),
  created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

-- 초기 데이터 (연습용, 비밀번호 평문)
INSERT INTO users (username, password, name, email) VALUES
  ('admin', 'a1234',  '관리자', 'admin@spaceshop.com'),
  ('hong',  'h1234',  '홍길동', 'hong@example.com'),
  ('park',  'p1234',  '박상희', 'kim@example.com'),
  ('ko',    'k1234',  '고담덕', 'lee@example.com');

COMMIT;

SELECT * FROM users;

-- admin 권한 변경
UPDATE users SET role = 'admin' WHERE id = 1;

-- 테이블 삭제 (처음부터 다시 만들 때만 실행)
DROP TABLE users;
  • UNIQUE는 같은 값이 두 번 저장되지 않게 막습니다. 아이디와 이메일은 중복 가입이 DB에서도 막힙니다.
  • username VARCHAR(16)은 회원가입 화면의 아이디 규칙(4~16자)과 길이를 맞춘 것입니다.
  • password VARCHAR(255)는 나중에 비밀번호를 암호화(해시)해 저장하면 길이가 길어지므로 넉넉하게 잡습니다.
  • role은 DEFAULT 'user'라서 초기 데이터에 적지 않으면 모두 일반 회원이 됩니다. 그래서 UPDATE로 관리자 권한을 따로 줍니다.
  • pgAdmin은 문장마다 자동으로 저장(auto commit)하므로 COMMIT;은 "진행 중인 트랜잭션이 없다"는 경고만 나오고 문제는 없습니다.
💡 주의 이 SQL을 전체 실행(F5)하면 마지막 DROP TABLE users;까지 실행되어 방금 만든 테이블이 삭제됩니다. 필요한 문장만 드래그해서 선택한 뒤 실행하세요.

💡 예제 — 6. 상품 API 서버 — ① DB 연결 · 기본 설정
server/index.js 
import express from 'express'
import pg from 'pg'

const app = express();
const PORT = 8000;

// postgreSQL 연결 설정
const db = new pg.Client({
  host: "localhost",
  user: "jsuser",
  password: "pwjs",
  database: "tsdb"
});

// postgreSQL 연결 확인
try {
  await db.connect();
  console.log("postgreSQL 연결 성공");
} catch (err) {
  console.error("postgreSQL 연결 실패:", err.message);
}

// 본문 요청 파싱
app.use(express.json());

// 기본 라우터
app.get("/", (req, res) => {
  res.send("<h2>REST API</h2>");
})

// ② 상품 API 라우터를 여기에 작성

// 서버 실행
app.listen(PORT, () => {
  console.log(`서버 실행중... http://localhost:${PORT}`);
})
  • new pg.Client({ ... })로 접속 정보를 만들고 await db.connect()로 연결합니다. 실패하면 catch에서 원인을 출력합니다.
  • 최상위 await: await는 원래 async 함수 안에서만 쓸 수 있었습니다. 그런데 ES 모듈(ESM)에서는 파일 맨 바깥(최상위)에서도 await를 쓸 수 있습니다. Node.js 14.8 이상에서 지원합니다. 이때는 모듈 전체가 비동기로 실행된다고 보면 됩니다. package.json에 "type": "module"을 넣은 이유이기도 합니다.
  • app.use(express.json())이 있어야 등록 · 수정 요청의 JSON 본문을 req.body로 꺼낼 수 있습니다.

💡 예제 — 6. 상품 API 서버 — ② 상품 목록 · 조회 · 등록 · 삭제 · 수정
server/index.js (① 기본 라우터 아래, 서버 실행 위에 추가) 
// 상품 목록
app.get("/api/products", async (req, res) => {
  const sql = "SELECT * FROM products";
  try {
    const result = await db.query(sql);
    res.json(result.rows);
  } catch (err) {
    console.log("상품 조회 오류!", err);
    res.status(500).send("상품 조회 중 오류가 발생했습니다.");
  }
});

// 상품 단건 조회
app.get("/api/products/:id", async (req, res) => {
  const pid = req.params.id;
  const sql = "SELECT * FROM products WHERE id = $1";
  try {
    const result = await db.query(sql, [pid]);
    res.json(result.rows[0]);
  } catch (err) {
    console.log("상품 조회 오류!", err);
    res.status(500).send("상품 조회 중 오류가 발생했습니다.");
  }
});

// 상품 등록
app.post("/api/products", async (req, res) => {
  const { pName, category, price, description } = req.body;
  const sql = "INSERT INTO products(p_name, category, price, description) "
        + "VALUES ($1, $2, $3, $4)";
  try{
    await db.query(sql, [pName, category, price, description]);
    res.send("상품 등록 완료!!");
  }catch(err){
    console.log("상품 등록 오류!", err);
    res.status(500).send("상품 등록 중 오류가 발생했습니다.");
  }
});

// 상품 삭제
app.delete("/api/products/:id", async (req, res) => {
  const pid = req.params.id;
  const sql = "DELETE FROM products WHERE id = $1";
  try {
    await db.query(sql, [pid]);
    res.send("상품 삭제 완료!!");
  } catch (err) {
    console.log("상품 삭제 오류!", err);
    res.status(500).send("상품 삭제 중 오류가 발생했습니다.");
  }
});

// 상품 수정
app.put("/api/products/:id", async (req, res) => {
  const pid = req.params.id;
  const { pName, category, price, description } = req.body;
  const sql = "UPDATE products SET p_name=$1, category=$2, price=$3, "
        + "description=$4 WHERE id=$5";
  try{
    await db.query(sql, [pName, category, price, description, pid]);
    res.send("상품 수정 완료!!");
  }catch(err){
    console.log("상품 수정 오류!", err);
    res.status(500).send("상품 수정 중 오류가 발생했습니다.");
  }      
});
  • PostgreSQL은 값 자리에 $1, $2 …를 쓰고, 실제 값은 배열로 따로 넘깁니다. 값을 SQL 문자열에 직접 이어 붙이지 않아 SQL 인젝션을 막습니다.
  • 조회 결과는 result.rows(배열)에 들어 있습니다. 단건 조회는 첫 번째 행 rows[0]을 보냅니다.
  • req.params.id는 주소의 :id, req.body는 요청 본문입니다.
💡 예제 — 7. Postman 테스트 (상품 등록)

  • Body → raw → JSON을 고르고 등록할 상품을 JSON으로 적습니다. 키 이름(pName, category, price, description)은 서버의 req.body에서 꺼내는 이름과 같아야 합니다.
  • 컬렉션(product)에 등록 · 목록 · 단건 조회 · 삭제 · 수정 요청을 저장해 두면 API를 고칠 때마다 다시 테스트하기 편합니다.
  • category는 테이블의 CHECK 목록에 있는 값만 저장됩니다. 다른 값을 보내면 서버가 500 오류를 돌려줍니다.
💡 예제 — 8. 회원 API (목록 · 가입 · 로그인)
server/index.js (상품 API 아래, 서버 실행 코드 위에 추가) 
// 회원 API
// 회원 목록
app.get("/api/users", async (req, res) => {
  // password는 빼고 필요한 컬럼만 조회합니다.
  const sql = "SELECT id, username, name, email, role, created_at FROM users";
  try {
    const result = await db.query(sql);
    res.json(result.rows);
  } catch (err) {
    console.log("회원 조회 오류!", err);
    res.status(500).send("회원 조회 중 오류가 발생했습니다.");
  }
});

// 회원 가입
app.post("/api/users", async (req, res) => {
  const { username, password, name, email} = req.body;
  const sql = "INSERT INTO users(username, password, name, email) "
        + "VALUES ($1, $2, $3, $4)";
  try{
    await db.query(sql, [username, password, name, email]);
    res.send("회원 가입 완료!!");
  }catch(err){
    console.log("회원 가입 오류!", err);
    res.status(500).send("회원 가입 중 오류가 발생했습니다.");
  }
});

// 로그인
app.post("/api/users/login", async (req, res) => {
  const { username, password } = req.body;
  // 비밀번호로 비교만 하고, 응답에는 password를 넣지 않습니다.
  const sql = "SELECT id, username, name, email, role, created_at FROM users "
        + "WHERE username = $1 AND password = $2";
  try {
    const result = await db.query(sql, [username, password]);
    if (result.rows.length === 0) {
      return res.status(401).send("아이디 또는 비밀번호가 올바르지 않습니다.");
    }

    res.json({
      message: "로그인 성공",
      user: result.rows[0]
    });
  } catch (err) {
    console.log("회원 로그인 오류!", err);
    res.status(500).send("로그인 중 오류가 발생했습니다.");
  }
});
  • 회원 가입은 role을 받지 않습니다. 테이블의 DEFAULT 'user'로 항상 일반 회원이 됩니다.
  • 로그인은 조회한 결과가 0건이면 아이디나 비밀번호가 틀린 것이므로 401(인증 실패)을 돌려줍니다. return을 붙여 아래 코드가 실행되지 않게 합니다.
  • 로그인처럼 정보를 조회하지만 비밀번호를 보내야 하는 요청은 GET(주소에 값이 보임) 대신 POST로 본문에 담아 보냅니다.
  • 프론트의 로그인 실패 메시지와 같게 무엇이 틀렸는지 알려 주지 않습니다.
  • 비밀번호는 응답에 넣지 않습니다. SELECT * 대신 필요한 컬럼만 적어 password를 뺍니다. 로그인은 WHERE에서 비밀번호를 비교만 하고, 돌려주는 회원 정보에는 비밀번호가 없습니다.

  • POST http://localhost:8000/api/users/login에 Body → raw → JSON으로 아이디와 비밀번호를 보냅니다.
  • 성공하면 200 OK와 함께 message, user가 돌아옵니다. 비밀번호를 틀리게 보내면 401 Unauthorized가 나옵니다.
  • 응답의 created_at은 UTC 기준(끝의 Z) 시각입니다. 한국 시간은 9시간을 더한 값입니다.
  • 위 캡처는 SELECT *를 쓰던 때라 응답에 password가 보입니다. 지금 코드처럼 컬럼을 골라 조회하면 응답에서 password가 빠집니다.

📖 CORS란?

브라우저는 보안을 위해 다른 주소(포트가 달라도 다른 주소)로 보내는 요청의 응답을 기본적으로 막습니다. React 개발 서버(5173)와 Express(8000)는 포트가 다르므로, 서버가 "이 요청은 받아도 된다"고 응답에 표시해 줘야 합니다. 이것을 CORS 허용이라고 합니다.

터미널 (server 폴더)

💡 예제 — ① 서버에 CORS 허용

import pg from 'pg'
import cors from 'cors'

const PORT = 8000;

// ... (postgreSQL 연결 코드는 그대로)

// 본문 요청 파싱

  • cors()는 모든 주소를 허용합니다. 배포할 때는 cors({ origin: 'https://내사이트주소' })처럼 허용할 주소를 정해 둡니다.

3 상품 API 연결

🎯 학습목표
  • 서버 응답 타입을 정하고 화면 타입으로 바꾸는 함수를 만들 수 있다.
  • useEffect로 화면이 처음 그려질 때 상품 목록을 불러올 수 있다.
  • 상품 등록 · 삭제 · 수정을 서버에 저장하고, 끝날 때까지 await로 기다릴 수 있다.
💡 예제 — ① 상품 요청 함수
src/api/products.ts 
import api from './api';
import type { Category, NewProduct, Product } from '../types/product';

// 서버(DB)가 돌려주는 상품 모양: 컬럼 이름 그대로 옵니다.
interface ProductRow {
  id: number;
  p_name: string;
  category: Category;
  price: number;
  description: string;
}

// 서버 모양 → 화면 모양(Product)으로 바꿉니다.
const toProduct = (row: ProductRow): Product => ({
  id: row.id,
  pName: row.p_name,
  category: row.category,
  price: row.price,
  description: row.description,
});

// 상품 목록 조회
export const getProducts = async () => {
  const response = await api.get<ProductRow[]>('/products');
  return response.data.map(toProduct);
}

// 상품 등록: 서버의 req.body에서 꺼내는 이름에 맞춰 보냅니다.
export const createProduct = async (product: NewProduct) => {
  await api.post('/products', {
    pName: product.pName,
    category: product.category,
    price: product.price,
    description: product.description,
  });
}

// 상품 삭제: 주소에 상품 번호를 붙여 DELETE 요청
export const deleteProduct = async (productId: number) => {
  await api.delete(`/products/${productId}`);
}

// 상품 수정: 주소에 상품 번호, 본문에 바뀐 값을 담아 PUT 요청
export const modifyProduct = async (product: Product) => {
  await api.put(`/products/${product.id}`, {
    pName: product.pName,
    category: product.category,
    price: product.price,
    description: product.description,
  });
}
  • ProductRow는 서버가 보내 주는 모양, Product는 화면이 쓰는 모양입니다. toProduct()가 둘을 이어 줍니다.
  • api.get<ProductRow[]>()처럼 제네릭으로 응답 타입을 알려 주면 response.data가 ProductRow[]가 됩니다.
  • 등록할 때는 반대로 서버의 req.body에서 꺼내는 이름(description)에 맞춰 보냅니다.
  • 삭제는 api.delete(), 수정은 api.put()으로 보냅니다. 어떤 상품인지는 주소의 /products/${productId}로 알려 줍니다. 서버의 DELETE /api/products/:id, PUT /api/products/:id와 짝이 맞습니다.
  • 상품 요청을 이 파일에 모아 두면 Provider는 어떻게 요청하는지 몰라도 됩니다.
💡 예제 — ② Context 타입 바꾸기
src/context/ProductContext.ts 
import type { Product, NewProduct } from "../types/product";
import { createContext, useContext } from "react";

// 상품 컨텍스트 타입 정의
// 서버에 저장하므로 끝날 때까지 기다릴 수 있게 함수들이 Promise를 돌려줍니다.
interface ProductContextType {
  products: Product[];
  addProduct: (newProduct: NewProduct) => Promise<void>;
  removeProduct: (productId: number) => Promise<void>;
  updateProduct: (updatedProduct: Product) => Promise<void>;
}

// 상품 컨텍스트 생성
export const ProductContext = createContext<ProductContextType | null>(null);

// 상품 컨텍스트 커스텀 훅
export const useProduct = () => {
  const context = useContext(ProductContext);
  if (!context) {
    throw new Error("useProduct는 ProductProvider 내부에서만 사용 가능합니다.");
  }
  return context;
};
💡 정리 10강의 Context 타입에서 바뀐 곳은 함수의 반환 타입뿐입니다. addProduct, removeProduct, updateProduct 모두 void → Promise<void>. 서버 저장은 시간이 걸리므로, 부르는 쪽에서 await로 기다릴 수 있게 합니다.
💡 예제 — ③ Provider가 서버에서 상품 불러오기
src/context/ProductProvider.tsx 
import React, { useEffect, useState } from "react";
import type { Product, NewProduct } from "../types/product";
import { ProductContext } from "./ProductContext";
import { createProduct, deleteProduct, getProducts, modifyProduct } from "../api/products";

const ProductProvider = ({ children }: { children: React.ReactNode }) => {
  // 처음에는 빈 배열로 시작하고, 서버에서 받아 오면 채웁니다.
  const [products, setProducts] = useState<Product[]>([]);

  // 화면이 처음 그려질 때 한 번 상품 목록을 불러옵니다.
  useEffect(() => {
    getProducts()
      .then(setProducts)
      .catch((err) => console.log('상품 목록 조회 오류!', err));
  }, []);

  // 상품 추가: 서버에 등록한 뒤, 서버가 만든 id를 받기 위해 목록을 다시 불러옵니다.
  const addProduct = async (newProduct: NewProduct) => {
    await createProduct(newProduct);
    setProducts(await getProducts());
  };

  // 상품 삭제: 서버에서 지운 뒤, 화면 목록에서도 뺍니다.
  const removeProduct = async (productId: number) => {
    await deleteProduct(productId);
    setProducts(products.filter((product) => product.id !== productId));
  };

  // 상품 수정: 서버에서 고친 뒤, 화면 목록에서도 같은 id의 상품을 바꿉니다.
  const updateProduct = async (updatedProduct: Product) => {
    await modifyProduct(updatedProduct);
    setProducts(products.map((product) =>
      product.id === updatedProduct.id ? updatedProduct : product
    ));
  };

  return (
    <ProductContext.Provider value={{ products, addProduct, removeProduct, updateProduct }}>
      {children}
    </ProductContext.Provider>
  );
}

export default ProductProvider;
  • 처음 값은 initialProducts 대신 빈 배열입니다. datas/products.ts는 이제 쓰지 않습니다.
  • useEffect(() => {...}, [])는 Provider가 처음 그려질 때 한 번만 실행됩니다. 여기서 목록을 불러와 setProducts로 채웁니다.
  • .then(setProducts)는 .then((list) => setProducts(list))를 줄여 쓴 것입니다.
  • 등록한 뒤 목록을 다시 불러오는 이유: 새 상품의 id는 DB(SERIAL)가 만들기 때문에 화면은 그 번호를 모릅니다.
  • 삭제 · 수정은 화면이 이미 id를 알고 있으므로 다시 불러오지 않고, 서버 요청이 성공한 뒤 10강과 같은 방식(filter, map)으로 화면 목록만 고칩니다.
  • 서버 요청이 실패하면 await에서 오류가 나서 아래 setProducts가 실행되지 않습니다. 그래서 DB와 화면이 어긋나지 않습니다.

4 회원 API 연결

🎯 학습목표
  • 회원 목록 · 로그인 · 회원가입 요청을 서버로 보내는 함수를 만들 수 있다.
  • 10강의 회원 Context를 그대로 두고, 함수의 반환 타입만 Promise로 바꿀 수 있다.
  • 서버 오류(401 등)를 try / catch로 받아 실패로 처리할 수 있다.
  • async 함수의 결과를 await로 기다려야 하는 이유를 설명할 수 있다.
💡 예제 — ① 회원 요청 함수
src/api/users.ts 
import api from './api';
import type { LoginForm, NewUser, User } from '../types/user';

interface LoginResponse {
  message: string;
  user: User;
}

// 회원 목록 조회
export const getUsers = async () => {
  const response = await api.get<User[]>('/users');
  return response.data;
}

// 로그인: 성공하면 회원 정보를 돌려주고, 실패(401)하면 오류가 납니다.
export const requestLogin = async (loginForm: LoginForm) => {
  const response = await api.post<LoginResponse>('/users/login', loginForm);
  return response.data.user;
}

// 회원 가입: role은 보내지 않습니다. 서버(DB)의 기본값 'user'가 들어갑니다.
export const createUser = async (newUser: NewUser) => {
  const { username, password, name, email } = newUser;
  await api.post('/users', { username, password, name, email });
}
  • getUsers() — 서버의 GET /api/users로 회원 목록을 받습니다. 가입 화면의 아이디 중복 검사(users.some)에 씁니다.
  • requestLogin(loginForm) — 10강의 LoginForm({ username, password })을 그대로 본문에 담아 보냅니다. 응답은 { message, user } 모양이므로 user만 꺼냅니다.
  • axios는 4xx, 5xx 응답이 오면 오류를 던집니다. 비밀번호가 틀려 401이 오면 부른 쪽의 catch로 갑니다.
  • createUser(newUser) — NewUser에는 role이 있지만 서버에는 보내지 않습니다. 가입하는 사람이 권한을 정할 수 없게 DB의 기본값('user')을 씁니다.
💡 예제 — ② Context 타입 바꾸기
src/context/UserContext.ts 
import { createContext, useContext } from "react";
import type {User, NewUser, LoginForm} from "../types/user"

// 회원 컨텍스트 타입 정의
// 서버에 물어봐야 하므로 signup · login은 Promise를 돌려줍니다.
interface UserContextType{
    users: User[];  // 회원목록
    currentUser: User | null;  // 로그인한 회원 (로그아웃 상태면 null)
    signup: (newUser: NewUser) => Promise<void>  // 회원가입
    login: (loginForm: LoginForm) => Promise<boolean>  // 로그인 (성공 여부 반환)
    logout: () => void  // 로그아웃
}

// 회원 컨텍스트 생성
export const UserContext = createContext<UserContextType | null>(null);

// 회원 컨텍스트 커스텀 Hook
export const useUser = () => {
    const context = useContext(UserContext);
    if(!context){
        throw new Error("useUser는 UserProvider 내부에서만 사용 가능합니다.")
    }
    return context
}
💡 정리 10강의 UserContextType에서 바뀐 곳은 반환 타입 두 개뿐입니다. signup: void → Promise<void>, login: boolean → Promise<boolean>. 이름(users, currentUser, signup, login, logout)은 그대로라서 Header 같은 화면은 고치지 않아도 됩니다.
💡 예제 — ③ Provider가 서버로 회원 목록 · 로그인 · 회원가입
src/context/UserProvider.tsx 
import { useEffect, useState } from "react"
import { UserContext } from "./UserContext"
import type {User, NewUser, LoginForm} from "../types/user"
import { createUser, getUsers, requestLogin } from "../api/users";

// UserProvider는 회원 저장소(repository) 역할
const UserProvider = ({children} : {children: React.ReactNode}) => {
    // 처음에는 빈 배열로 시작하고, 서버에서 받아 오면 채웁니다.
    const [users, setUsers] = useState<User[]>([]);
    const [currentUser, setCurrentUser] = useState<User | null>(null);

    // 화면이 처음 그려질 때 한 번 회원 목록을 불러옵니다.
    useEffect(() => {
        getUsers()
            .then(setUsers)
            .catch((err) => console.log('회원 목록 조회 오류!', err));
    }, []);

    // 회원가입 함수: 서버(DB)에 저장한 뒤, DB가 만든 id를 받기 위해 목록을 다시 불러옵니다.
    const signup = async (newUser: NewUser) => {
        await createUser(newUser);
        setUsers(await getUsers());
    }

    // 로그인 함수 (성공하면 true, 실패하면 false 반환)
    // 서버가 회원 정보를 돌려주면 성공, 오류(401 등)가 나면 실패입니다.
    const login = async (loginForm: LoginForm) => {
        try {
            const user = await requestLogin(loginForm);
            setCurrentUser(user);
            return true;
        } catch {
            return false;
        }
    }

    // 로그아웃 함수
    const logout = () => {
        setCurrentUser(null);
    }

    return(
        <UserContext.Provider value={{
            users, 
            currentUser, 
            signup, 
            login, 
            logout
        }}>
            {children}
        </UserContext.Provider>
    )
}

export default UserProvider
  • 처음 값은 initialUsers 대신 빈 배열입니다. datas/users.ts는 이제 쓰지 않고, useEffect로 서버에서 회원 목록을 불러옵니다.
  • 회원가입: 서버에 저장한 뒤 목록을 다시 불러옵니다. 새 회원의 id는 DB(SERIAL)가 만들기 때문입니다. 상품 등록과 같은 방식입니다.
  • 로그인: 10강은 users.find로 직접 찾았지만, 이제는 서버가 아이디 · 비밀번호를 비교합니다. 성공하면 서버가 돌려준 회원을 currentUser에 넣고 true, 오류가 나면 catch에서 false를 돌려줍니다.
  • 로그아웃: 10강과 같습니다. currentUser를 null로 비웁니다.
💡 예제 — ④ 로그인 화면에서 기다리기
src/users/SignIn.tsx (handleSubmit) 
  // 폼 제출 핸들러
  const handleSubmit = async (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();

    // 유효성 검사
    if(!username.trim()){
      setError("아이디를 입력해주세요");
      return;
    }
    if(!password){
      setError("비밀번호를 입력해주세요");
      return;
    }

    // 로그인 함수 호출 (성공하면 true)
    // login은 Promise를 돌려주므로 await로 결과를 기다립니다.
    const success = await login({ username: username.trim(), password });
    if(!success){
      setError("아이디 또는 비밀번호가 올바르지 않습니다");
      return;
    }

    alert("로그인되었습니다.");
    navigate('/');  // 상품 목록으로 이동
  }
  • handleSubmit 앞에 async, login(...) 앞에 await를 붙입니다. 나머지는 10강 그대로입니다.
💡 주의 await를 빼면 success에는 true/false가 아니라 Promise 객체가 들어갑니다. Promise 객체는 항상 참이라 !success가 늘 false가 되어, 비밀번호가 틀려도 목록으로 이동합니다.
💡 예제 — ⑤ 회원가입 화면에서 기다리기
src/users/SignUp.tsx (handleSubmit 일부) 
    // 회원가입 함수 호출 (passwordConfirm은 제외, 권한은 일반 회원)
    try {
      // 서버에 저장이 끝날 때까지 기다립니다.

        email: email.trim(),

  • handleSubmit 앞에 async를 붙이고, signup(...)을 try 안에서 await로 기다립니다. 입력값 검사와 users.some 중복 검사는 10강 그대로입니다.
  • users는 서버에서 불러온 목록이라, 다른 사람이 가입한 아이디도 중복 검사에 걸립니다.
  • 그 사이 다른 사람이 같은 아이디로 가입하면 DB의 UNIQUE 때문에 서버가 오류를 돌려주고, catch에서 오류 메시지를 보여 줍니다.

📖 정리

  1. React와 Express는 포트가 달라 CORS를 허용해야 요청을 주고받을 수 있다.
  2. 서버 주소는 axios 인스턴스 한 곳에서 관리한다.
  3. DB 이름과 화면 이름이 다르면 응답을 받는 곳에서 한 번만 바꾼다(toProduct).
  4. Context의 이름과 모양은 10강 그대로 두고, Provider만 서버를 쓰도록 바꾸면 화면 컴포넌트는 거의 그대로 쓸 수 있다.
  5. 서버 요청은 시간이 걸리므로 Promise를 돌려주고, 부르는 쪽은 await로 기다린다.
