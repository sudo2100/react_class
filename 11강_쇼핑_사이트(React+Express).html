📖 package.json에 "type": "module" 추가

{
  "name": "server",
  "version": "1.0.0",
  "main": "index.js",
  "type": "module"
}

"type": "module"을 넣어야 import express from 'express'처럼 import 문법과 파일 맨 위의 await를 쓸 수 있습니다. 넣지 않으면 Node는 예전 방식(const express = require('express'))으로 읽기 때문에 import에서 오류가 납니다.

💡 예제 — 5. PostgreSQL 연결 — ① 계정 · DB 생성 (postgres 계정 / postgres DB)
pgAdmin 4 — Query Tool 
-- postgres(계정), postgres(DB) 접속

-- 계정 생성: 이미 존재하는 계정이면 생략하고 DB 생성 문장만 선택해 실행
CREATE USER jsuser WITH PASSWORD 'pwjs';

-- DB 생성 (jsuser를 소유자로 지정)
CREATE DATABASE tsdb OWNER jsuser;
  • 관리자 계정(postgres)으로 postgres DB에 접속해서 실행합니다.
  • 한 줄씩 블록으로 선택한 뒤 실행(F5)합니다. 여러 문장을 한꺼번에 실행하면 CREATE DATABASE에서 cannot run inside a transaction block 오류가 날 수 있습니다.
  • 수업용 계정 jsuser를 만들고, tsdb DB의 소유자로 지정합니다. 소유자는 그 DB 안에서 테이블을 만들고 고칠 수 있습니다.
💡 참고 — jsuser가 이미 있는 경우 앞 강의에서 jsuser 계정을 이미 만들었다면 CREATE USER는 role "jsuser" already exists 오류가 납니다. 계정은 PostgreSQL 서버 전체에서 하나만 있으면 되므로, 이때는 CREATE DATABASE tsdb OWNER jsuser; 한 줄만 선택해 실행해서 기존 계정을 새 DB의 소유자로 지정합니다. 비밀번호도 앞에서 정한 pwjs를 그대로 씁니다.

💡 예제 — 5. PostgreSQL 연결 — ③ DB 연결 · 기본 설정
server/index.js 
import express from 'express'
import pg from 'pg'

const app = express();
const PORT = 8000;

// postgreSQL 연결 설정
const db = new pg.Client({
  host: "localhost",
  user: "jsuser",
  password: "pwjs",
  database: "tsdb"
});

// postgreSQL 연결 확인
try {
  await db.connect();
  console.log("postgreSQL 연결 성공");
} catch (err) {
  console.error("postgreSQL 연결 실패:", err.message);
}

// 본문 요청 파싱
app.use(express.json());

// 기본 라우터
app.get("/", (req, res) => {
  res.send("<h2>REST API</h2>");
})

// 2단원 상품 API · 3단원 회원 API 라우터를 여기에 작성

// 서버 실행
app.listen(PORT, () => {
  console.log(`서버 실행중... http://localhost:${PORT}`);
})
  • new pg.Client({ ... })로 접속 정보를 만들고 await db.connect()로 연결합니다. 실패하면 catch에서 원인을 출력합니다.
  • 최상위 await: await는 원래 async 함수 안에서만 쓸 수 있었습니다. 그런데 ES 모듈(ESM)에서는 파일 맨 바깥(최상위)에서도 await를 쓸 수 있습니다. Node.js 14.8 이상에서 지원합니다. 이때는 모듈 전체가 비동기로 실행된다고 보면 됩니다. package.json에 "type": "module"을 넣은 이유이기도 합니다.
  • app.use(express.json())이 있어야 등록 · 수정 요청의 JSON 본문을 req.body로 꺼낼 수 있습니다.

💡 예제 — 5. PostgreSQL 연결 — ④ 상품 테이블 · 초기 데이터 (jsuser 계정 / tsdb DB)
pgAdmin 4 — Query Tool 
CREATE TABLE products (
  id          SERIAL PRIMARY KEY,
  p_name      VARCHAR(100) NOT NULL,
  category    VARCHAR(20)  NOT NULL
              CHECK (category IN ('마우스', '키보드', '모니터', '주변기기')),
  price       INTEGER      NOT NULL CHECK (price >= 0),
  description TEXT         NOT NULL DEFAULT '',
  image       VARCHAR(255),          -- 이미지 경로 (없으면 NULL)
  created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

-- 초기 데이터
INSERT INTO products (p_name, category, price, description, image) VALUES
  ('무선 마우스',        '마우스',   25000,  '조용한 클릭음의 2.4GHz 무선 마우스', '/images/mouse.png'),
  ('기계식 키보드',      '키보드',   89000,  '청축 스위치, RGB 백라이트', '/images/keyboard.png');

-- 커밋 수행
COMMIT;
  • jsuser 계정으로 tsdb DB에 접속해서 실행합니다. 그래야 테이블의 소유자가 jsuser가 됩니다.
  • SERIAL은 번호를 자동으로 1씩 증가시킵니다. 등록할 때 id를 넣지 않아도 됩니다.
  • CHECK는 들어갈 수 있는 값을 DB에서 한 번 더 막습니다. 카테고리는 목록에 있는 값만, 가격은 0 이상만 저장됩니다.
  • DEFAULT는 값을 넣지 않았을 때의 기본값입니다. created_at에는 저장한 시각(NOW())이 자동으로 들어갑니다.
  • PostgreSQL은 이름을 소문자로 다루므로 컬럼 이름은 p_name처럼 소문자와 밑줄로 짓습니다.
  • image에는 이미지 파일이 아니라 경로(/images/mouse.png)를 저장합니다. 파일은 React 프로젝트의 client/public/images/에 둡니다(10강 11단원).
  • image에는 NOT NULL이 없어서 값을 넣지 않으면 NULL이 됩니다. 이미지가 없는 상품에는 화면에서 기본 이미지를 보여 줍니다.
💡 예제 — 5. PostgreSQL 연결 — ⑤ 회원 테이블 · 초기 데이터 (jsuser 계정 / tsdb DB)
pgAdmin 4 — Query Tool 
CREATE TABLE users (
  id          SERIAL PRIMARY KEY,
  username    VARCHAR(12)  NOT NULL UNIQUE,
  password    VARCHAR(255) NOT NULL,
  name        VARCHAR(50)  NOT NULL,
  email       VARCHAR(100) NOT NULL UNIQUE,
  role        VARCHAR(10)  NOT NULL DEFAULT 'user'
              CHECK (role IN ('user', 'admin')),
  created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

-- 초기 데이터 (연습용, 비밀번호 평문)
INSERT INTO users (username, password, name, email, role) VALUES
  ('admin0', 'a1234567', '관리자', 'admin0@spaceshop.com', 'admin'),
  ('ko12',  'k1234567',  '고담덕', 'ko12@example.com',  'user');
  • UNIQUE는 같은 값이 두 번 저장되지 않게 막습니다. 아이디와 이메일은 중복 가입이 DB에서도 막힙니다.
  • username VARCHAR(12)는 회원가입 화면의 아이디 규칙(4~12자)과 길이를 맞춘 것입니다.
  • password VARCHAR(255)는 나중에 비밀번호를 암호화(해시)해 저장하면 길이가 길어지므로 넉넉하게 잡습니다.
  • 초기 데이터에서 role을 직접 넣어 관리자('admin')를 지정합니다. 적지 않으면 DEFAULT 'user'로 일반 회원이 됩니다.

2 상품 API 서버

🎯 학습목표
  • 상품 목록 · 단건 조회 · 등록 · 수정 · 삭제 API를 만들 수 있다.
  • 값 자리에 $1, $2 …를 써서 SQL 인젝션을 막을 수 있다.
  • Postman으로 상품 API를 테스트할 수 있다.
💡 예제 — ① 상품 목록 · 조회 · 등록
server/index.js (1단원 5-③ 기본 라우터 아래, 서버 실행 위에 추가) 
// 상품 목록
app.get("/api/products", async (req, res) => {
  const sql = "SELECT * FROM products";
  try {
    const result = await db.query(sql);
    res.json(result.rows);
  } catch (err) {
    console.log("상품 조회 오류!", err);
    res.status(500).send("상품 조회 중 오류가 발생했습니다.");
  }
});

// 상품 단건 조회
app.get("/api/products/:id", async (req, res) => {
  const pid = req.params.id;
  const sql = "SELECT * FROM products WHERE id = $1";
  try {
    const result = await db.query(sql, [pid]);
    res.json(result.rows[0]);
  } catch (err) {
    console.log("상품 조회 오류!", err);
    res.status(500).send("상품 조회 중 오류가 발생했습니다.");
  }
});

// 상품 등록
app.post("/api/products", async (req, res) => {
  const { pName, category, price, description, image } = req.body;
  const sql = "INSERT INTO products(p_name, category, price, description, image) "
        + "VALUES ($1, $2, $3, $4, $5)";
  try{
    // image를 보내지 않으면 undefined → null로 저장
    await db.query(sql, [pName, category, price, description, image ?? null]);
    res.send("상품 등록 완료!!");
  }catch(err){
    console.log("상품 등록 오류!", err);
    res.status(500).send("상품 등록 중 오류가 발생했습니다.");
  }
});
  • PostgreSQL은 값 자리에 $1, $2 …를 쓰고, 실제 값은 배열로 따로 넘깁니다. 값을 SQL 문자열에 직접 이어 붙이지 않아 SQL 인젝션을 막습니다.
  • 조회 결과는 result.rows(배열)에 들어 있습니다. 단건 조회는 첫 번째 행 rows[0]을 보냅니다.
  • 조회는 SELECT *라서 image도 함께 보냅니다. 등록(INSERT)은 보낸 image를 저장하고, 보내지 않으면 image ?? null로 NULL을 저장합니다.
  • req.params.id는 주소의 :id, req.body는 요청 본문입니다.
💡 테스트 (상품 목록 조회)
  • GET http://localhost:8000/api/products를 보내면 200 OK와 함께 상품 목록이 JSON 배열로 옵니다.
  • 응답에 image("/images/mouse.png")가 들어 있습니다. 서버가 SELECT *로 조회해서 테이블의 모든 컬럼을 보내기 때문입니다.
  • 이름은 DB 컬럼 그대로(p_name, created_at)입니다. 화면 이름(pName)으로는 5단원의 toProduct()에서 바꿉니다.

Body → raw → JSON 
{
  "pName": "25인치 모니터",
  "category": "모니터",
  "price": 179000,
  "description": "QHD 해상도, 165Hz 주사율",
  "image": "/images/monitor.png"

  • Body → raw → JSON을 고르고 등록할 상품을 JSON으로 적습니다. 키 이름(pName, category, price, description, image)은 서버의 req.body에서 꺼내는 이름과 같아야 합니다.
  • image는 빼도 됩니다. 빼고 보내면 서버가 image ?? null로 NULL을 저장하고, 화면에는 기본 이미지가 나옵니다.
  • 컬렉션(product)에 등록 · 목록 · 단건 조회 · 삭제 · 수정 요청을 저장해 두면 API를 고칠 때마다 다시 테스트하기 편합니다.
  • category는 테이블의 CHECK 목록에 있는 값만 저장됩니다. 다른 값을 보내면 서버가 500 오류를 돌려줍니다.
💡 예제 — ② 상품 삭제 · 수정
server/index.js (① 상품 등록 아래에 추가) 
// 상품 삭제
app.delete("/api/products/:id", async (req, res) => {

  try {
    await db.query(sql, [pid]);

  } catch (err) {
    console.log("상품 삭제 오류!", err);
    res.status(500).send("상품 삭제 중 오류가 발생했습니다.");

// 상품 수정
app.put("/api/products/:id", async (req, res) => {
  const pid = req.params.id;
  const { pName, category, price, description, image } = req.body;
  const sql = "UPDATE products SET p_name=$1, category=$2, price=$3, "
        + "description=$4, image=$5 WHERE id=$6";
  try{
    // image를 보내지 않으면 null로 저장되므로, 수정할 때는 기존 image도 함께 보냅니다.
    await db.query(sql, [pName, category, price, description, image ?? null, pid]);
    res.send("상품 수정 완료!!");
  }catch(err){
    console.log("상품 수정 오류!", err);
    res.status(500).send("상품 수정 중 오류가 발생했습니다.");
  }      
});
  • 삭제 · 수정은 주소의 :id(req.params.id)로 어떤 상품인지 정합니다. WHERE id = … 조건을 빼먹으면 모든 상품이 지워지거나 바뀌므로 주의합니다.
  • 수정은 바뀐 값을 req.body에서 꺼내고, 상품 번호는 마지막 자리 $6으로 넘깁니다. 배열 순서가 $1 ~ $6과 같아야 합니다.
  • 수정(UPDATE)은 image도 함께 바꿉니다. image를 빼고 보내면 image ?? null 때문에 이미지가 지워지므로, Postman으로 테스트할 때도 기존 image를 함께 보냅니다.

  • 본문에는 바꾸지 않는 값까지 모든 값을 보냅니다. 서버가 다섯 컬럼을 한 번에 바꾸기 때문입니다. 특히 image를 빼면 이미지가 NULL로 지워집니다.
  • 성공하면 상품 수정 완료!!가 돌아옵니다. GET /api/products/3으로 다시 조회해 바뀐 값을 확인합니다.

5 상품 API 연결

🎯 학습목표
  • 서버 응답 타입을 정하고 화면 타입으로 바꾸는 함수를 만들 수 있다.
  • useEffect로 화면이 처음 그려질 때 상품 목록을 불러올 수 있다.
  • 상품 등록 · 삭제 · 수정을 서버에 저장하고, 끝날 때까지 await로 기다릴 수 있다.
  • 상품을 등록할 때 이미지 경로도 함께 DB에 저장할 수 있다.
💡 예제 — ① 상품 요청 함수
src/api/products.ts 
import api from './api';
import type { Category, NewProduct, Product } from '../types/product';

// 서버(DB)가 돌려주는 상품 모양: 컬럼 이름 그대로 옵니다.
interface ProductRow {
  id: number;
  p_name: string;
  category: Category;
  price: number;
  description: string;
  image: string | null;  // 이미지가 없으면 DB에서 null이 옵니다.
}

// 서버 모양 → 화면 모양(Product)으로 바꿉니다.
const toProduct = (row: ProductRow): Product => ({
  id: row.id,
  pName: row.p_name,
  category: row.category,
  price: row.price,
  description: row.description,
  image: row.image ?? undefined,  // null → undefined (화면 타입은 image?: string)
});

// 상품 목록 조회
export const getProducts = async () => {
  const response = await api.get<ProductRow[]>('/products');
  return response.data.map(toProduct);
}

// 상품 등록: 서버의 req.body에서 꺼내는 이름에 맞춰 보냅니다.
export const createProduct = async (product: NewProduct) => {
  await api.post('/products', {
    pName: product.pName,
    category: product.category,
    price: product.price,
    description: product.description,
    image: product.image,  // 없으면(undefined) 보내지 않음 → 서버에서 null
  });
}

// 상품 삭제: 주소에 상품 번호를 붙여 DELETE 요청
export const deleteProduct = async (productId: number) => {
  await api.delete(`/products/${productId}`);
}

// 상품 수정: 주소에 상품 번호, 본문에 바뀐 값을 담아 PUT 요청
export const modifyProduct = async (product: Product) => {
  await api.put(`/products/${product.id}`, {
    pName: product.pName,
    category: product.category,
    price: product.price,
    description: product.description,
    image: product.image,  // 기존 이미지 경로도 함께 보내야 지워지지 않음
  });
}
  • ProductRow는 서버가 보내 주는 모양, Product는 화면이 쓰는 모양입니다. toProduct()가 둘을 이어 줍니다.
  • image — DB의 빈 값은 null이지만 화면 타입은 10강 11단원의 image?: string(string 또는 undefined)입니다. row.image ?? undefined로 null을 undefined로 바꿉니다. 그대로 넣으면 Type 'string | null' is not assignable to type 'string | undefined' 오류가 납니다.
  • api.get<ProductRow[]>()처럼 제네릭으로 응답 타입을 알려 주면 response.data가 ProductRow[]가 됩니다.
  • 등록할 때는 반대로 서버의 req.body에서 꺼내는 이름(description, image)에 맞춰 보냅니다. image가 undefined이면 JSON으로 바꿀 때 빠지므로, 서버에서는 null로 저장됩니다.
  • 삭제는 api.delete(), 수정은 api.put()으로 보냅니다. 어떤 상품인지는 주소의 /products/${productId}로 알려 줍니다. 서버의 DELETE /api/products/:id, PUT /api/products/:id와 짝이 맞습니다. 수정할 때는 image도 보내서, 이미지를 바꾸지 않으면 원래 경로가 그대로 다시 저장됩니다.
  • 상품 요청을 이 파일에 모아 두면 Provider는 어떻게 요청하는지 몰라도 됩니다.
💡 상품 이미지 상품 타입(image?: string), 상품 카드 · 상세의 <img>(product.image ?? NO_IMAGE)는 10강 11단원 그대로 씁니다. 이미지 파일은 서버가 아니라 React 프로젝트의 client/public/images/에 둡니다.
shop-mall/ ├─ client/ │ ├─ public/ │ │ └─ images/ ← 10강 11단원의 이미지 6개 │ └─ src/ └─ server/
💡 예제 — ② Context 타입 바꾸기
src/context/ProductContext.ts 
import type { Product, NewProduct } from "../types/product";
import { createContext, useContext } from "react";

// 상품 컨텍스트 타입 정의
// 서버에 저장하므로 끝날 때까지 기다릴 수 있게 함수들이 Promise를 돌려줍니다.
interface ProductContextType {
  products: Product[];
  addProduct: (newProduct: NewProduct) => Promise<void>;
  removeProduct: (productId: number) => Promise<void>;
  updateProduct: (updatedProduct: Product) => Promise<void>;
}

// 상품 컨텍스트 생성
export const ProductContext = createContext<ProductContextType | null>(null);

// 상품 컨텍스트 커스텀 훅
export const useProduct = () => {
  const context = useContext(ProductContext);
  if (!context) {
    throw new Error("useProduct는 ProductProvider 내부에서만 사용 가능합니다.");
  }
  return context;
};
💡 정리 10강의 Context 타입에서 바뀐 곳은 함수의 반환 타입뿐입니다. addProduct, removeProduct, updateProduct 모두 void → Promise<void>. 서버 저장은 시간이 걸리므로, 부르는 쪽에서 await로 기다릴 수 있게 합니다.
💡 예제 — ③ Provider가 서버에서 상품 불러오기
src/context/ProductProvider.tsx 
import React, { useEffect, useState } from "react";
import type { Product, NewProduct } from "../types/product";
import { ProductContext } from "./ProductContext";
import { createProduct, deleteProduct, getProducts, modifyProduct } from "../api/products";

const ProductProvider = ({ children }: { children: React.ReactNode }) => {
  // 처음에는 빈 배열로 시작하고, 서버에서 받아 오면 채웁니다.
  const [products, setProducts] = useState<Product[]>([]);

  // 화면이 처음 그려질 때 한 번 상품 목록을 불러옵니다.
  useEffect(() => {
    getProducts()
      .then(setProducts)
      .catch((err) => console.log('상품 목록 조회 오류!', err));
  }, []);

  // 상품 추가: 서버에 등록한 뒤, 서버가 만든 id를 받기 위해 목록을 다시 불러옵니다.
  const addProduct = async (newProduct: NewProduct) => {
    await createProduct(newProduct);
    setProducts(await getProducts());
  };

  // 상품 삭제: 서버에서 지운 뒤, 화면 목록에서도 뺍니다.
  const removeProduct = async (productId: number) => {
    await deleteProduct(productId);
    setProducts(products.filter((product) => product.id !== productId));
  };

  // 상품 수정: 서버에서 고친 뒤, 화면 목록에서도 같은 id의 상품을 바꿉니다.
  const updateProduct = async (updatedProduct: Product) => {
    await modifyProduct(updatedProduct);
    setProducts(products.map((product) =>
      product.id === updatedProduct.id ? updatedProduct : product
    ));
  };

  return (
    <ProductContext.Provider value={{ products, addProduct, removeProduct, updateProduct }}>
      {children}
    </ProductContext.Provider>
  );
}

  • 서버 요청이 실패하면 await에서 오류가 나서 아래 setProducts가 실행되지 않습니다. 그래서 DB와 화면이 어긋나지 않습니다.

6 회원 API 연결

🎯 학습목표
  • 회원 목록 · 로그인 · 회원가입 요청을 서버로 보내는 함수를 만들 수 있다.
  • 10강의 회원 Context를 그대로 두고, 함수의 반환 타입만 Promise로 바꿀 수 있다.
  • 서버 오류(401 등)를 try / catch로 받아 실패로 처리할 수 있다.
  • async 함수의 결과를 await로 기다려야 하는 이유를 설명할 수 있다.
💡 예제 — ① 회원 요청 함수
src/api/users.ts 
import api from './api';
import type { LoginForm, NewUser, User } from '../types/user';

interface LoginResponse {
  message: string;
  user: User;
}

// 회원 목록 조회
export const getUsers = async () => {
  const response = await api.get<User[]>('/users');
  return response.data;
}

// 로그인: 성공하면 회원 정보를 돌려주고, 실패(401)하면 오류가 납니다.
export const requestLogin = async (loginForm: LoginForm) => {
  const response = await api.post<LoginResponse>('/users/login', loginForm);
  return response.data.user;
}

// 회원 가입: role은 보내지 않습니다. 서버(DB)의 기본값 'user'가 들어갑니다.
export const createUser = async (newUser: NewUser) => {
  const { username, password, name, email } = newUser;
  await api.post('/users', { username, password, name, email });
}
  • getUsers() — 서버의 GET /api/users로 회원 목록을 받습니다. 가입 화면의 아이디 중복 검사(users.some)에 씁니다.
  • requestLogin(loginForm) — 10강의 LoginForm({ username, password })을 그대로 본문에 담아 보냅니다. 응답은 { message, user } 모양이므로 user만 꺼냅니다.
  • axios는 4xx, 5xx 응답이 오면 오류를 던집니다. 비밀번호가 틀려 401이 오면 부른 쪽의 catch로 갑니다.
  • createUser(newUser) — NewUser에는 role이 있지만 서버에는 보내지 않습니다. 가입하는 사람이 권한을 정할 수 없게 DB의 기본값('user')을 씁니다.
💡 예제 — ② Context 타입 바꾸기
src/context/UserContext.ts 
import { createContext, useContext } from "react";
import type {User, NewUser, LoginForm} from "../types/user"

// 회원 컨텍스트 타입 정의
// 서버에 물어봐야 하므로 signup · login은 Promise를 돌려줍니다.
interface UserContextType{
    users: User[];  // 회원목록
    currentUser: User | null;  // 로그인한 회원 (로그아웃 상태면 null)
    signup: (newUser: NewUser) => Promise<void>  // 회원가입
    login: (loginForm: LoginForm) => Promise<boolean>  // 로그인 (성공 여부 반환)
    logout: () => void  // 로그아웃
}

// 회원 컨텍스트 생성
export const UserContext = createContext<UserContextType | null>(null);

// 회원 컨텍스트 커스텀 Hook
export const useUser = () => {
    const context = useContext(UserContext);
    if(!context){
        throw new Error("useUser는 UserProvider 내부에서만 사용 가능합니다.")
    }
    return context
}
💡 정리 10강의 UserContextType에서 바뀐 곳은 반환 타입 두 개뿐입니다. signup: void → Promise<void>, login: boolean → Promise<boolean>. 이름(users, currentUser, signup, login, logout)은 그대로라서 Header 같은 화면은 고치지 않아도 됩니다.
💡 예제 — ③ Provider가 서버로 회원 목록 · 로그인 · 회원가입
src/context/UserProvider.tsx 
import { useEffect, useState } from "react"
import { UserContext } from "./UserContext"
import type {User, NewUser, LoginForm} from "../types/user"
import { createUser, getUsers, requestLogin } from "../api/users";

// UserProvider는 회원 저장소(repository) 역할
const UserProvider = ({children} : {children: React.ReactNode}) => {
    // 처음에는 빈 배열로 시작하고, 서버에서 받아 오면 채웁니다.
    const [users, setUsers] = useState<User[]>([]);
    const [currentUser, setCurrentUser] = useState<User | null>(null);

    // 화면이 처음 그려질 때 한 번 회원 목록을 불러옵니다.
    useEffect(() => {
        getUsers()
            .then(setUsers)
            .catch((err) => console.log('회원 목록 조회 오류!', err));
    }, []);

    // 회원가입 함수: 서버(DB)에 저장한 뒤, DB가 만든 id를 받기 위해 목록을 다시 불러옵니다.
    const signup = async (newUser: NewUser) => {
        await createUser(newUser);
        setUsers(await getUsers());
    }

    // 로그인 함수 (성공하면 true, 실패하면 false 반환)
    // 서버가 회원 정보를 돌려주면 성공, 오류(401 등)가 나면 실패입니다.
    const login = async (loginForm: LoginForm) => {
        try {
            const user = await requestLogin(loginForm);
            setCurrentUser(user);
            return true;
        } catch {
            return false;
        }
    }

    // 로그아웃 함수
    const logout = () => {
        setCurrentUser(null);
    }

    return(
        <UserContext.Provider value={{
            users, 
            currentUser, 
            signup, 
            login, 
            logout
        }}>
            {children}
        </UserContext.Provider>
    )
}

export default UserProvider
  • 처음 값은 initialUsers 대신 빈 배열입니다. datas/users.ts는 이제 쓰지 않고, useEffect로 서버에서 회원 목록을 불러옵니다.
  • 회원가입: 서버에 저장한 뒤 목록을 다시 불러옵니다. 새 회원의 id는 DB(SERIAL)가 만들기 때문입니다. 상품 등록과 같은 방식입니다.
  • 로그인: 10강은 users.find로 직접 찾았지만, 이제는 서버가 아이디 · 비밀번호를 비교합니다. 성공하면 서버가 돌려준 회원을 currentUser에 넣고 true, 오류가 나면 catch에서 false를 돌려줍니다.
  • 로그아웃: 10강과 같습니다. currentUser를 null로 비웁니다.

📖 정리

  1. React와 Express는 포트가 달라 CORS를 허용해야 요청을 주고받을 수 있다.
  2. 서버 주소는 axios 인스턴스 한 곳에서 관리한다.
  3. DB 이름과 화면 이름이 다르면 응답을 받는 곳에서 한 번만 바꾼다(toProduct).
  4. Context의 이름과 모양은 10강 그대로 두고, Provider만 서버를 쓰도록 바꾸면 화면 컴포넌트는 거의 그대로 쓸 수 있다.
  5. 서버 요청은 시간이 걸리므로 Promise를 돌려주고, 부르는 쪽은 await로 기다린다.

📖 비밀번호 암호화(해시)란?

지금은 비밀번호를 입력한 그대로(평문) DB에 저장합니다. DB가 유출되거나 관리자가 테이블을 열어 보면 모든 회원의 비밀번호가 그대로 보입니다. 그래서 비밀번호는 해시(hash)로 바꿔 저장합니다. 해시는 한 방향으로만 바꿀 수 있어서, 저장된 값으로 원래 비밀번호를 알아낼 수 없습니다.

평문 저장 (지금) 해시 저장 (바꾼 뒤) password: a1234567 → password: $2b$10$N5rsqdDHx35mzc89Z66sGu... [회원 가입] a1234567 → bcrypt.hash() → $2b$10$... 를 DB에 저장 [로그인] 입력한 a1234567 + DB의 $2b$10$... → bcrypt.compare() → true / false
  • bcrypt는 비밀번호 해시에 널리 쓰는 라이브러리입니다. 같은 비밀번호라도 매번 다른 솔트(salt, 무작위 값)를 섞어서 해시가 달라집니다.
  • 해시는 되돌릴 수 없으므로, 로그인할 때는 입력한 비밀번호를 같은 방법으로 해시해 비교합니다(bcrypt.compare()).
  • 화면(React) 코드는 고치지 않습니다. 암호화는 서버에서 합니다.

// 로그인
app.post("/api/users/login", async (req, res) => {
  const { username, password } = req.body;
  // 1. 아이디로만 회원을 찾습니다. (암호화된 비밀번호는 SQL로 비교할 수 없음)
  const sql = "SELECT * FROM users WHERE username = $1";
  try {
    const result = await db.query(sql, [username]);
    const user = result.rows[0];

    // 2. 회원이 없거나, 입력한 비밀번호와 저장된 해시가 맞지 않으면 실패
    if (!user || !(await bcrypt.compare(password, user.password))) {
      return res.status(401).send("아이디 또는 비밀번호가 올바르지 않습니다.");
    }

    // 3. 응답에서 비밀번호를 빼고 나머지만 보냅니다.
    const { password: _, ...userInfo } = user;
    res.json({
      message: "로그인 성공",
      user: userInfo
    });
  } catch (err) {
    console.log("회원 로그인 오류!", err);
    res.status(500).send("로그인 중 오류가 발생했습니다.");
  }
});
  • 전에는 WHERE username = $1 AND password = $2로 SQL에서 비교했지만, 이제 DB에는 해시가 있으므로 아이디로만 찾습니다.
  • bcrypt.compare(입력한 비밀번호, 저장된 해시)가 true이면 비밀번호가 맞습니다.
  • 회원이 없을 때와 비밀번호가 틀릴 때 같은 메시지 · 같은 401을 돌려줍니다. 어느 쪽이 틀렸는지 알려 주지 않기 위해서입니다.
  • const {{ password: _, ...userInfo }} = user — 구조 분해로 password만 빼고 나머지를 userInfo에 모읍니다. 응답에 해시도 보내지 않습니다.

// 업로드한 파일을 저장할 위치와 파일 이름
const storage = multer.diskStorage({
  destination: "uploads/",  // server/uploads 폴더 (없으면 자동으로 만듦)
  filename: (req, file, cb) => {
    // 이름이 겹치지 않도록 시간으로 이름을 짓고 확장자는 그대로 둡니다.
    // 예) 1731100000000.png
    const ext = path.extname(file.originalname);
    cb(null, Date.now() + ext);
  }
});

const upload = multer({
  storage,
  // 이미지 파일만 받습니다.
  fileFilter: (req, file, cb) => cb(null, file.mimetype.startsWith("image/")),
  limits: { fileSize: 5 * 1024 * 1024 }  // 5MB까지
});

// uploads 폴더의 파일을 http://localhost:8000/uploads/파일명 으로 열 수 있게 합니다.
app.use("/uploads", express.static("uploads"));

// 이미지 업로드: form-data의 image 필드로 파일 1개를 받습니다.
app.post("/api/upload", upload.single("image"), (req, res) => {
  if (!req.file) {
    return res.status(400).send("이미지 파일만 올릴 수 있습니다.");
  }
  // DB에 저장할 경로를 돌려줍니다.
  res.json({ image: `/uploads/${req.file.filename}` });
});
  • multer.diskStorage() — 받은 파일을 어디에(destination), 어떤 이름으로(filename) 저장할지 정합니다. 원래 파일 이름을 그대로 쓰면 이름이 겹치거나 한글 · 공백이 섞이므로 Date.now()로 새 이름을 짓습니다.
  • fileFilter로 이미지만 받고, limits.fileSize로 5MB보다 큰 파일을 막습니다. 이미지가 아니면 req.file이 없으므로 400을 돌려줍니다.
  • upload.single("image") — form-data의 image 칸에 담긴 파일 1개를 받아 req.file에 넣습니다.
  • express.static("uploads") — uploads 폴더의 파일을 주소로 열 수 있게 합니다. /uploads/1731100000000.png → http://localhost:8000/uploads/1731100000000.png
  • 응답으로 파일이 아니라 경로(/uploads/…)를 돌려줍니다. 이 경로를 상품 등록 때 image로 보내 DB에 저장합니다. 상품 등록 API는 고치지 않습니다.

src/api/products.ts 
import api from './api';
import type { Category, NewProduct, Product } from '../types/product';

// 서버(DB)가 돌려주는 상품 모양: 컬럼 이름 그대로 옵니다.
interface ProductRow {
  id: number;
  p_name: string;
  category: Category;
  price: number;
  description: string;
  image: string | null;  // 이미지가 없으면 DB에서 null이 옵니다.
}

// 서버 주소: 업로드한 이미지는 서버에 있으므로 서버 주소를 붙여야 열립니다.
const SERVER_URL = 'http://localhost:8000';

// DB의 이미지 경로 → 화면에서 쓸 주소
// /uploads/... (업로드한 이미지)는 서버 주소를 붙이고, /images/... (public 폴더)는 그대로 씁니다.
const toImageUrl = (image: string | null) => {
  if (!image) return undefined;
  return image.startsWith('/uploads/') ? SERVER_URL + image : image;
};

// 서버 모양 → 화면 모양(Product)으로 바꿉니다.
const toProduct = (row: ProductRow): Product => ({
  id: row.id,
  pName: row.p_name,
  category: row.category,
  price: row.price,
  description: row.description,
  image: toImageUrl(row.image),  // null → undefined, /uploads/... → 서버 주소 붙이기
});

// 상품 목록 조회
export const getProducts = async () => {
  const response = await api.get<ProductRow[]>('/products');
  return response.data.map(toProduct);
}

// 상품 등록: 서버의 req.body에서 꺼내는 이름에 맞춰 보냅니다.
export const createProduct = async (product: NewProduct) => {
  await api.post('/products', {
    pName: product.pName,
    category: product.category,
    price: product.price,
    description: product.description,
    image: product.image,  // 없으면(undefined) 보내지 않음 → 서버에서 null
  });
}

// 상품 삭제: 주소에 상품 번호를 붙여 DELETE 요청
export const deleteProduct = async (productId: number) => {
  await api.delete(`/products/${productId}`);
}

// 상품 수정: 주소에 상품 번호, 본문에 바뀐 값을 담아 PUT 요청
export const modifyProduct = async (product: Product) => {
  await api.put(`/products/${product.id}`, {
    pName: product.pName,
    category: product.category,
    price: product.price,
    description: product.description,
    // 기존 이미지 경로도 함께 보내야 지워지지 않음 (붙였던 서버 주소는 떼고 보냄)
    image: product.image?.replace(SERVER_URL, ''),
  });
}

// 이미지 업로드: 파일을 form-data로 보내고, 서버에 저장된 경로를 받습니다.
export const uploadImage = async (file: File) => {
  const formData = new FormData();
  formData.append('image', file);  // 서버의 upload.single("image")와 같은 이름
  const response = await api.post<{ image: string }>('/upload', formData);
  return response.data.image;  // 예) "/uploads/1731100000000.png"
}
  • uploadImage(file) — FormData에 파일을 image라는 이름으로 담아 보냅니다. 서버의 upload.single("image")와 이름이 같아야 합니다. axios가 FormData를 보면 알아서 multipart/form-data로 보냅니다.
  • toImageUrl() — 업로드한 이미지(/uploads/…)는 서버(8000)에 있고, 처음 넣은 이미지(/images/…)는 React(5173)의 public에 있습니다. /uploads/로 시작하면 서버 주소를 붙여 <img>가 서버에서 이미지를 가져오게 합니다.
  • modifyProduct — 화면의 image에는 서버 주소가 붙어 있으므로 replace(SERVER_URL, '')로 떼고 보내, DB에는 항상 /uploads/… 모양만 저장되게 합니다.

import type { ProductForm } from "../types/product";
import { useProduct } from "../context/ProductContext";
import { uploadImage } from "../api/products";
import { useRef, useState } from "react";
import { useNavigate } from "react-router-dom";

// 초기 폼 데이터
const initialForm: ProductForm = {
  pName: "",
  category: "마우스",
  price: 0,
  description: "",
};

const AddProduct = () => {
  const {addProduct} = useProduct();
  const [form, setForm] = useState<ProductForm>(initialForm);
  const [error, setError] = useState<string | null>(null);
  const [imageFile, setImageFile] = useState<File | null>(null);  // 고른 이미지 파일
  const [preview, setPreview] = useState<string | null>(null);    // 미리보기 주소
  const fileRef = useRef<HTMLInputElement>(null);                  // 파일 입력창 (취소할 때 비우기용)

  // 폼 데이터 구조 분해 할당
  const {pName, category, price, description} = form;
  const navigate = useNavigate();

  // 입력값 변경 핸들러
  const handleChange = (
    e: React.ChangeEvent<HTMLInputElement | HTMLSelectElement | HTMLTextAreaElement>) => {
    const { name, value } = e.target;
    setForm({
      ...form,
      [name]: value
    });
  };

  // 이미지 파일 선택 핸들러
  const handleImageChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const file = e.target.files?.[0] ?? null;  // 고른 파일 1개 (고르지 않으면 null)
    setImageFile(file);
    // 내 컴퓨터의 파일을 브라우저에서 잠깐 보여 줄 수 있는 주소로 만듭니다.
    setPreview(file ? URL.createObjectURL(file) : null);
  };

  // 폼 제출 핸들러
  const handleSubmit = async (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    // 유효성 검사
    if(!pName.trim()){
      setError("상품명을 입력해주세요.");
      return;
    }
    if(!price || price <= 0){
      setError("가격을 올바르게 입력해주세요.");
      return;
    }
    if(!description.trim()){
      setError("설명을 입력해주세요.");
      return;
    }

    // 상품 추가
    try {
      // 1. 이미지를 골랐으면 먼저 서버에 올리고, 저장된 경로를 받습니다.
      const image = imageFile ? await uploadImage(imageFile) : undefined;

      // 2. 받은 경로와 함께 상품을 등록합니다.
      await addProduct({
        pName, 
        category, 
        price: Number(price), 
        description,
        image
      });
      alert("상품이 등록되었습니다.");
      // 상품 목록 페이지로 이동
      navigate('/');
    } catch {
      setError("상품 등록 중 오류가 발생했습니다.");
    }
  }

  // 폼 초기화 핸들러
  const handleCancel = () => {
    setForm(initialForm);
    setError(null);
    setImageFile(null);
    setPreview(null);
    if (fileRef.current) fileRef.current.value = "";  // 파일 입력창도 비웁니다.
  };

  return (
    <div className="product-add"> 
      <h2>상품 등록</h2>
      <form onSubmit={handleSubmit}>
        <div>
          <label htmlFor="pName">상품명:</label>
          <input
            type="text"
            id="pName"
            name="pName"
            value={pName}
            onChange={handleChange}
          />
        </div>
        <div>
          <label htmlFor="category">카테고리:</label>
          <select
            id="category"
            name="category"
            value={category}
            onChange={handleChange}
          >
            <option value="마우스">마우스</option>
            <option value="키보드">키보드</option>
            <option value="모니터">모니터</option>
            <option value="주변기기">주변기기</option>
          </select>
        </div>
        <div>
          <label htmlFor="price">가격:</label>
          <input
            type="number"
            id="price"
            name="price"
            value={price}
            onChange={handleChange}
          />
        </div>
        <div>
          <label htmlFor="description">설명:</label>
          <textarea
            id="description"
            name="description"
            value={description}
            onChange={handleChange}
          />
        </div>
        <div>
          <label htmlFor="image">이미지:</label>
          <input
            type="file"
            id="image"
            accept="image/*"
            ref={fileRef}
            onChange={handleImageChange}
          />
          {preview && <img className="product-add_preview" src={preview} alt="미리보기" />}
        </div>
        {error && <p className="product-add_error">{error}</p>}
        <div className="product-add_buttons">
          <button type="submit">등록</button>
          <button type="button" onClick={handleCancel}>취소</button>
        </div>
      </form>
    </div>
  )
}

📖 정리 — 이미지 파일 업로드 흐름

정리하면, 5단원 ⑤는 public/images/에 미리 넣어 둔 이미지 중에서 고르는 방법이고, 이 단원에서는 내 컴퓨터의 이미지 파일을 골라 서버에 올린 뒤 서버가 저장한 경로를 DB에 넣었습니다. 파일은 JSON으로 보낼 수 없어서 form-data로 보내고, 서버는 multer로 받았습니다.

[이미지를 고른 경우] 파일 선택 → 미리보기(URL.createObjectURL) 등록 버튼 → uploadImage(파일) ── POST /api/upload (form-data) ──▶ server/uploads/1731100000000.png 저장 ◀── { image: "/uploads/1731100000000.png" } → addProduct({ ..., image }) ── POST /api/products ──▶ DB image 컬럼에 경로 저장 목록 → toImageUrl → <img src="http://localhost:8000/uploads/1731100000000.png"> [이미지를 고르지 않은 경우] image: undefined → DB NULL → 화면에 기본 이미지(no-image.png)

src/products/EditProduct.tsx 
import { useRef, useState } from "react";
import { Link, useNavigate, useParams } from "react-router-dom";
import type { Product, ProductForm } from "../types/product";
import { useProduct } from "../context/ProductContext";
import { useUser } from "../context/UserContext";
import { uploadImage } from "../api/products";

// 이미지가 없는 상품에 보여 줄 기본 이미지
const NO_IMAGE = "/images/no-image.png";

// 수정 폼: 찾은 상품(product)을 받아 처음 값으로 씁니다.
const EditProductForm = ({ product }: { product: Product }) => {
  const { updateProduct } = useProduct();
  const navigate = useNavigate();

  // 처음 값 = 지금 상품의 값
  const initialForm: ProductForm = {
    pName: product.pName,
    category: product.category,
    price: product.price,
    description: product.description,
  };
  const [form, setForm] = useState<ProductForm>(initialForm);
  const [error, setError] = useState<string | null>(null);
  const [imageFile, setImageFile] = useState<File | null>(null);  // 새로 고른 이미지 파일
  const [preview, setPreview] = useState<string | null>(null);    // 새 이미지 미리보기 주소
  const fileRef = useRef<HTMLInputElement>(null);

  const {pName, category, price, description} = form;

  // 입력값 변경 핸들러
  const handleChange = (
    e: React.ChangeEvent<HTMLInputElement | HTMLSelectElement | HTMLTextAreaElement>) => {
    const { name, value } = e.target;
    setForm({
      ...form,
      [name]: value
    });
  };

  // 이미지 파일 선택 핸들러
  const handleImageChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const file = e.target.files?.[0] ?? null;
    setImageFile(file);
    setPreview(file ? URL.createObjectURL(file) : null);
  };

  // 폼 제출 핸들러
  const handleSubmit = async (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    // 유효성 검사
    if(!pName.trim()){
      setError("상품명을 입력해주세요.");
      return;
    }
    if(!price || price <= 0){
      setError("가격을 올바르게 입력해주세요.");
      return;
    }
    if(!description.trim()){
      setError("설명을 입력해주세요.");
      return;
    }

    try {
      // 새 이미지를 골랐으면 서버에 올리고, 아니면 기존 이미지를 그대로 씁니다.
      const image = imageFile ? await uploadImage(imageFile) : product.image;

      // id는 그대로 두고 나머지 값을 바꿉니다.
      await updateProduct({
        id: product.id,
        pName,
        category,
        price: Number(price),
        description,
        image
      });
      alert("상품이 수정되었습니다.");
      // 수정한 상품의 상세 화면으로 이동
      navigate(`/product/${product.id}`);
    } catch {
      setError("상품 수정 중 오류가 발생했습니다.");
    }
  }

  // 되돌리기 핸들러: 처음 값(지금 상품의 값)으로 돌아갑니다.
  const handleReset = () => {
    setForm(initialForm);
    setError(null);
    setImageFile(null);
    setPreview(null);
    if (fileRef.current) fileRef.current.value = "";
  };

  return (
    <div className="product-add">
      <h2>상품 수정</h2>
      <form onSubmit={handleSubmit}>
        <div>
          <label htmlFor="pName">상품명:</label>
          <input
            type="text"
            id="pName"
            name="pName"
            value={pName}
            onChange={handleChange}
          />
        </div>
        <div>
          <label htmlFor="category">카테고리:</label>
          <select
            id="category"
            name="category"
            value={category}
            onChange={handleChange}
          >
            <option value="마우스">마우스</option>
            <option value="키보드">키보드</option>
            <option value="모니터">모니터</option>
            <option value="주변기기">주변기기</option>
          </select>
        </div>
        <div>
          <label htmlFor="price">가격:</label>
          <input
            type="number"
            id="price"
            name="price"
            value={price}
            onChange={handleChange}
          />
        </div>
        <div>
          <label htmlFor="description">설명:</label>
          <textarea
            id="description"
            name="description"
            value={description}
            onChange={handleChange}
          />
        </div>
        <div>
          <label htmlFor="image">이미지:</label>
          {/* 새 이미지를 고르면 미리보기, 아니면 지금 이미지를 보여 줍니다. */}
          <img
            className="product-add_preview"
            src={preview ?? product.image ?? NO_IMAGE}
            alt={product.pName}
          />
          <input
            type="file"
            id="image"
            accept="image/*"
            ref={fileRef}
            onChange={handleImageChange}
          />
        </div>
        {error && <p className="product-add_error">{error}</p>}
        <div className="product-add_buttons">
          <button type="submit">저장</button>
          <button type="button" onClick={handleReset}>되돌리기</button>
          <button type="button" onClick={() => navigate(`/product/${product.id}`)}>취소</button>
        </div>
      </form>
    </div>
  )
}

// 수정 화면: 주소의 id로 상품을 찾아 수정 폼에 넘깁니다.
const EditProduct = () => {
  const { id } = useParams<{ id: string }>();
  const { products } = useProduct();
  const { currentUser } = useUser();

  // 관리자만 수정 가능 (주소창에 직접 입력해도 막기)
  if (currentUser?.role !== 'admin') {
    return (
      <div className="product-add">
        <p>관리자만 상품을 수정할 수 있습니다.</p>
        <Link to="/signin">로그인</Link>
      </div>
    );
  }

  const product = products.find((p) => p.id === Number(id));

  // 상품 목록을 아직 불러오는 중이거나 없는 상품이면
  if (!product) {
    return <div>상품을 찾을 수 없습니다.</div>;
  }

  return <EditProductForm product={product} />;
}

export default EditProduct

  • 컴포넌트를 둘로 나눈 이유: 상품 목록은 서버에서 늦게 도착하므로, 주소창에 /product/3/edit을 바로 입력하면 처음에는 product가 없습니다. useState(처음 값)은 처음 한 번만 쓰이므로, EditProduct가 상품을 찾은 뒤에 EditProductForm을 그려야 처음 값이 제대로 들어갑니다.
  • 이미지: 새 파일을 고르면 미리보기를, 아니면 지금 이미지(product.image)를 보여 줍니다. 저장할 때 새 파일이 없으면 product.image를 그대로 보내 이미지가 지워지지 않습니다.
  • id는 바꾸지 않고 그대로 넘깁니다. 서버는 주소의 :id로 어떤 상품인지 찾습니다.
  • 관리자 확인은 상세 화면의 버튼뿐 아니라 수정 화면에서도 합니다. 주소창에 직접 입력해 들어올 수 있기 때문입니다.

올릴 것Render 서비스필요한 주소
PostgreSQLPostgres만들면 DB 주소(URL)가 생김
server (Express)Web ServiceDB 주소 → 환경 변수 DATABASE_URL
client (React)Static Site서버 주소 → 환경 변수 VITE_API_URL

환경 변수는 코드 밖에서 넣어 주는 설정 값입니다. 코드는 같게 두고, 내 컴퓨터와 Render에서 값만 다르게 줄 수 있습니다. 비밀번호가 들어 있는 DB 주소를 깃허브에 올리지 않아도 됩니다.

const api = axios.create({

📖 정리

  1. 배포 순서는 DB → 서버 → React이고, 앞에서 만든 주소를 다음 단계의 환경 변수로 넣는다.
  2. 서버는 process.env.DATABASE_URL · process.env.PORT, React는 import.meta.env.VITE_API_URL로 환경 변수를 읽는다.
  3. 서버는 Render 안에서 Internal DB 주소를, pgAdmin은 External DB 주소(SSL)를 쓴다.
  4. 무료 플랜은 서버가 잠들고, 업로드 파일이 지워지고, DB가 30일 뒤 만료된다.
