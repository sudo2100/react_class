1 Express 프레임워크 소개

🎯 학습목표
  • Express 프레임워크가 무엇인지, 어디에 쓰이는지 이해한다.
  • Express로 만드는 가장 기본적인 서버 코드의 형태를 파악한다.

📖 Express 프레임워크란?

Express는 Node.js 기반에서 동작하는 웹 서버 프레임워크로, 서버 개발을 쉽고 빠르게 할 수 있도록 도와주는 가볍고 유연한 백엔드 도구입니다.

주로 다음과 같은 곳에서 사용합니다.

  • REST API 서버 — 데이터를 주고받는 API 제공
  • 프론트엔드(React 등) 백엔드 — SPA에 데이터를 공급하는 서버
  • 간단한 웹 서버 — 정적/동적 페이지 응답
  • 풀스택 프로젝트 — 프론트와 백엔드를 함께 구성
💡 정리 Express 공식 문서(expressjs.com)의 슬로건은 "Fast, unopinionated, minimalist web framework for Node.js"입니다. 설치는 npm install express --save 로 합니다.
💡 예제 — Express 공식 예제(가장 기본 형태)
index.js 
const express = require('express')
const app = express()
const port = 3000

app.get('/', (req, res) => {
  res.send('Hello World!')
})

app.listen(port, () => {
  console.log(`Example app listening on port ${port}`)
})

2 api-server 프로젝트 시작 (package.json · index.js)

🎯 학습목표
  • Node.js 프로젝트를 초기화하고 Express를 설치할 수 있다.
  • package.json의 "type": "module" 설정으로 ES6 import 구문을 사용할 수 있다.
  • 가장 기본적인 Express 서버(index.js)를 작성할 수 있다.

import express from 'express';

const app = express();

// 라우트 설정

📖 서버 자동 실행 — nodemon

node index.js는 코드를 고칠 때마다 서버를 껐다 켜야 합니다. nodemon을 설치하면 파일이 바뀔 때마다 서버가 자동으로 재실행됩니다.

1. 설치 → npm i nodemon 2. 실행 → nodemon index (또는 npx nodemon index) 3. 스크립트 실행 → npm run dev
💡 예제 — nodemon 설치 및 실행
터미널 
npm i nodemon
nodemon index         # 실행
npx nodemon index     # 실행 (nodemon 명령을 찾지 못할 때)
package.json 
"scripts": {
  "test": "echo \"Error: no test specified\" && exit 1",
  "start": "nodemon index.js"
},
package.json (scripts 추가) 
"scripts": {
  "test": "echo \"Error: no test specified\" && exit 1",
  "dev": "nodemon index.js"
},
터미널 (scripts로 실행) 
npm run dev           # 실행

4 REST API 만들기 — 상품 목록 · 등록

🎯 학습목표
  • REST API와 HTTP 메서드(GET · POST · PUT · DELETE)의 역할을 이해한다.
  • app.get으로 상품 목록을 JSON으로 응답하는 API를 만들 수 있다.
  • express.json() 미들웨어로 요청 본문(req.body)을 파싱할 수 있다.

📖 RESTful API와 HTTP 메서드

메서드의미Express 코드
GET조회app.get(url) → res.json(data)
POST생성app.post(url) → req.body(data)
PUT수정app.put(url)
DELETE삭제app.delete(url)
💡 정리 POST 요청처럼 요청 본문(body)에 담긴 JSON 데이터를 req.body로 읽으려면 app.use(express.json()) 미들웨어를 반드시 등록해야 합니다.
💡 예제 — 상품 목록 API (GET)
index.js 
// 상품 목록
app.get("/api/products", (req, res) => {
  const products = [
    {id:1, name: "무선 마우스", price: 30000},
    {id:2, name: "유선 키보드", price: 20000},
    {id:3, name: "웹캠", price: 50000},
  ]
  res.json(products);  //json 형태로 응답
});
브라우저 출력

http://localhost:8000/api/products (pretty print 적용):

💡 예제 — 상품 등록 API (POST) + JSON 미들웨어
index.js 
// 요청 본문을 JSON 형태로 파싱하기 위한 미들웨어
app.use(express.json());

// 상품 등록
// postman에서 Body - raw - JSON 선택 후 데이터 전송
app.post("/api/products", (req, res) => {
  console.log(req.body); // { id: 4, name: '모니터', price: 100000 }
  res.send('상품이 등록되었습니다.');
});

정답 보기

5 Postman으로 API 테스트하기 + 전체 코드

🎯 학습목표
  • Postman을 설치하고 Workspace · Collection을 구성할 수 있다.
  • POST 요청의 Body에 JSON을 담아 API를 테스트할 수 있다.
  • 미들웨어 · 로깅 · GET · POST를 포함한 전체 서버 코드를 이해한다.

📖 Postman — REST API 테스트 도구

브라우저는 주소창으로 GET 요청만 편하게 보낼 수 있습니다. POST/PUT/DELETE처럼 본문이 필요한 요청을 테스트하려면 Postman 같은 테스트 도구가 필요합니다.

Postman 설치 → My Workspace > COLLECTION > 추가 → 요청(Method + URL) 생성 → Body > raw > JSON 선택 후 데이터 입력 → Send
💡 예제 — Postman 설치

Postman 다운로드 페이지에서 Windows x64를 내려받아 설치합니다.

💡 예제 — My Workspace > COLLECTION > 추가

My Workspace에서 COLLECTION을 추가하고, 그 안에 GET·POST 요청을 만들어 테스트합니다.

💡 예제 — POST 요청 보내기 (Postman)
Postman → POST http://localhost:8000/api/products → Body(raw, JSON) 
{
  "id": 4,
  "name": "모니터",
  "price": 100000
}
브라우저 출력

상품이 등록되었습니다.

💡 예제 — 전체 코드 (미들웨어 · 로깅 · GET · POST)
index.js 
import express from 'express'

const app = express(); // express 앱 생성

// 기본 라우트 설정
app.get("/", (req, res) => {
  res.send("<h2>Hello, World!</h2>");
});

// 상품 목록
app.get("/api/products", (req, res) => {
  const products = [
    {id:1, name: "무선 마우스", price: 30000},
    {id:2, name: "유선 키보드", price: 20000},
    {id:3, name: "웹캠", price: 50000},
  ]
  res.json(products);  //json 형태로 응답
});

// 요청 본문을 JSON 형태로 파싱하기 위한 미들웨어

// 상품 등록
// postman에서 Body - raw - JSON 선택 후 데이터 전송
app.post("/api/products", (req, res) => {
  console.log(req.body); // { id: 4, name: '모니터', price: 100000 }
  res.send('상품이 등록되었습니다.');
});

// 서버 실행
const PORT = 8000
app.listen(PORT, () => {
  console.log(`서버 실행중... http://localhost:${PORT}`);
});

📖 MySQL DBMS 설치

웹 애플리케이션에서 데이터베이스와의 연동은 필수적인 작업입니다. 이런 상호작용을 위해서는 데이터베이스 관리 시스템(DBMS)이 설치되어야 합니다.

① 'mysql download' 검색 → MySQL Community Downloads ② 8.4.8 LTS 버전 선택 → 설치 ③ 설치 정보 입력 - 사용자 : root - 비밀번호 : pw1234 - 포트 : 3306
💡 정리 MySQL Workbench(워크벤치)는 MySQL 데이터베이스를 시각적으로 관리하고 설계할 수 있도록 돕는 통합 개발 환경(IDE)입니다. 설치 후 root 계정으로 접속합니다.

📖 MySQL 데이터 타입(Data Type)

데이터 타입설명
CHAR고정길이 문자, 최대 255byte, 디폴트값은 1byte
VARCHAR가변길이 문자, 최대 65536byte, 디폴트값은 1byte
INT가변 숫자, 십진수 기준 최대 220byte
TEXT가변길이 문자, 최대 65536byte, 디폴트값은 1byte
DATE날짜 — 연, 월, 일
TIMESTAMP날짜 — 연, 월, 일, 시, 분, 초, 밀리초

📖 ER 다이어그램 — 부서와 사원의 개체 관계도

[부서] ── <소속> ── [사원] │ │ 부서번호 부서이름 위치 사원번호 사원이름 나이

사각형은 개체(엔티티), 마름모는 관계, 타원은 속성(칼럼)을 나타냅니다.

📖 제약 조건(Constraints)

테이블들은 각 속성(칼럼)에 대한 무결성을 유지하기 위한 다양한 제약 조건이 적용되어 있습니다. 제약 조건에는 NOT NULL, 기본키, 외래키, CHECK 등이 있습니다.

제약 조건설명
NOT NULL칼럼을 정의할 때 명시하면 반드시 데이터를 입력해야 한다.
칼럼명 데이터타입 NOT NULL

Workbench SQL Editor 
-- 사원 테이블 생성
create table employee(
  id varchar(5) primary key,
  name varchar(20) not null,
  salary int
);

-- 사원 추가
insert into employee(id, name, salary) values ('e1001', '김대리', 3500000);
insert into employee(id, name, salary) values ('e1002', '장그래', 2500000);
-- insert into employee(id, name) values ('e1002', '한강');
-- Error Code: 1062. Duplicate entry 'e1002' for key 'employee.PRIMARY'

insert into employee(id, name) values ('e1003', '한강');
-- insert into employee(id, salary) values ('e1004', 5000000);
-- Error Code: 1364. Field 'name' doesn't have a default value

-- 사원 검색
select * from employee;

-- 아이디가 'e1001'인 사원의 이름과 급여 검색
select name, salary from employee where id = 'e1001';

-- 급여가 300만원 미만인 사원의 모든 정보 검색
select * from employee where salary < 3000000;

-- 급여가 없는 사원의 정보 검색
select * from employee where salary is null;
✏️ 실습문제

실습 6-3. 오류 코드 해석하기

기본키가 id인 employee 테이블에서 Error Code: 1062. Duplicate entry 'e1002'와 Error Code: 1364. Field 'name' doesn't have a default value가 각각 왜 발생하는지 설명하세요.

정답 보기
  • 1062: 이미 존재하는 기본키 값('e1002')을 또 삽입하려 해서 발생합니다. PRIMARY KEY는 UNIQUE 속성을 가지므로 값이 중복될 수 없습니다.
  • 1364: name 컬럼이 NOT NULL인데 값을 넣지 않아 발생합니다. 기본값도 없으므로 반드시 값을 입력해야 합니다.
