1 Express 프레임워크 소개

🎯 학습목표
  • Express 프레임워크가 무엇인지, 어디에 쓰이는지 이해한다.
  • Express로 만드는 가장 기본적인 서버 코드의 형태를 파악한다.

📖 Express 프레임워크란?

Express는 Node.js 기반에서 동작하는 웹 서버 프레임워크로, 서버 개발을 쉽고 빠르게 할 수 있도록 도와주는 가볍고 유연한 백엔드 도구입니다.

주로 다음과 같은 곳에서 사용합니다.

  • REST API 서버 — 데이터를 주고받는 API 제공
  • 프론트엔드(React 등) 백엔드 — SPA에 데이터를 공급하는 서버
  • 간단한 웹 서버 — 정적/동적 페이지 응답
  • 풀스택 프로젝트 — 프론트와 백엔드를 함께 구성
💡 정리 Express 공식 문서(expressjs.com)의 슬로건은 "Fast, unopinionated, minimalist web framework for Node.js"입니다. 설치는 npm install express --save 로 합니다.
💡 예제 — Express 공식 예제(가장 기본 형태)
index.js 
const express = require('express')
const app = express()
const port = 3000

app.get('/', (req, res) => {
  res.send('Hello World!')
})

app.listen(port, () => {
  console.log(`Example app listening on port ${port}`)
})

2 api-server 프로젝트 시작 (package.json · index.js)

🎯 학습목표
  • Node.js 프로젝트를 초기화하고 Express를 설치할 수 있다.
  • package.json의 "type": "module" 설정으로 ES6 import 구문을 사용할 수 있다.
  • 가장 기본적인 Express 서버(index.js)를 작성할 수 있다.

📖 서버 자동 실행 — nodemon

node index.js는 코드를 고칠 때마다 서버를 껐다 켜야 합니다. nodemon을 설치하면 파일이 바뀔 때마다 서버가 자동으로 재실행됩니다.

1. 설치 → npm i nodemon 2. 실행 → nodemon index (또는 npx nodemon index) 3. 스크립트 실행 → npm run dev
💡 예제 — nodemon 설치 및 실행
터미널 
npm i nodemon
nodemon index         # 실행
npx nodemon index     # 실행 (nodemon 명령을 찾지 못할 때)
package.json 
"scripts": {
  "test": "echo \"Error: no test specified\" && exit 1",
  "start": "nodemon index.js"
},
package.json (scripts 추가) 
"scripts": {
  "test": "echo \"Error: no test specified\" && exit 1",
  "dev": "nodemon index.js"
},
터미널 (scripts로 실행) 
npm run dev           # 실행

4 REST API 만들기 — 상품 목록 · 등록

🎯 학습목표
  • REST API와 HTTP 메서드(GET · POST · PUT · DELETE)의 역할을 이해한다.
  • app.get으로 상품 목록을 JSON으로 응답하는 API를 만들 수 있다.
  • express.json() 미들웨어로 요청 본문(req.body)을 파싱할 수 있다.

📖 RESTful API와 HTTP 메서드

메서드의미Express 코드
GET조회app.get(url) → res.json(data)
POST생성app.post(url) → req.body(data)
PUT수정app.put(url)
DELETE삭제app.delete(url)
💡 정리 POST 요청처럼 요청 본문(body)에 담긴 JSON 데이터를 req.body로 읽으려면 app.use(express.json()) 미들웨어를 반드시 등록해야 합니다.
💡 예제 — 상품 목록 API (GET)
index.js 
// 상품 목록
app.get("/api/products", (req, res) => {
  const products = [
    {id:1, name: "무선 마우스", price: 30000},
    {id:2, name: "유선 키보드", price: 20000},
    {id:3, name: "웹캠", price: 50000},
  ]
  res.json(products);  //json 형태로 응답
});
브라우저 출력

http://localhost:8000/api/products (pretty print 적용):

💡 예제 — 상품 등록 API (POST) + JSON 미들웨어
index.js 
// 요청 본문을 JSON 형태로 파싱하기 위한 미들웨어
app.use(express.json());

// 상품 등록
// postman에서 Body - raw - JSON 선택 후 데이터 전송
app.post("/api/products", (req, res) => {
  console.log(req.body); // { id: 4, name: '모니터', price: 100000 }
  res.send('상품이 등록되었습니다.');
});

정답 보기

5 Postman으로 API 테스트하기 + 전체 코드

🎯 학습목표
  • Postman을 설치하고 Workspace · Collection을 구성할 수 있다.
  • POST 요청의 Body에 JSON을 담아 API를 테스트할 수 있다.
  • 미들웨어 · 로깅 · GET · POST를 포함한 전체 서버 코드를 이해한다.

📖 Postman — REST API 테스트 도구

브라우저는 주소창으로 GET 요청만 편하게 보낼 수 있습니다. POST/PUT/DELETE처럼 본문이 필요한 요청을 테스트하려면 Postman 같은 테스트 도구가 필요합니다.

Postman 설치 → My Workspace > COLLECTION > 추가 → 요청(Method + URL) 생성 → Body > raw > JSON 선택 후 데이터 입력 → Send
💡 예제 — Postman 설치

Postman 다운로드 페이지에서 Windows x64를 내려받아 설치합니다.

💡 예제 — My Workspace > COLLECTION > 추가

My Workspace에서 COLLECTION을 추가하고, 그 안에 GET·POST 요청을 만들어 테스트합니다.

💡 예제 — POST 요청 보내기 (Postman)
Postman → POST http://localhost:8000/api/products → Body(raw, JSON) 
{
  "id": 4,
  "name": "모니터",
  "price": 100000
}

💡 예제 — 전체 코드 (미들웨어 · 로깅 · GET · POST)
index.js 
import express from 'express'

const app = express(); // express 앱 생성

// 기본 라우트 설정
app.get("/", (req, res) => {
  res.send("<h2>Hello, World!</h2>");
});

// 상품 목록
app.get("/api/products", (req, res) => {
  const products = [
    {id:1, name: "무선 마우스", price: 30000},
    {id:2, name: "유선 키보드", price: 20000},
    {id:3, name: "웹캠", price: 50000},

  console.log(req.body); // { id: 4, name: '모니터', price: 100000 }

// 서버 실행
const PORT = 8000
app.listen(PORT, () => {
  console.log(`서버 실행중... http://localhost:${PORT}`);

6 MySQL 설치·데이터 타입, 테이블 만들기와 제약 조건

🎯 학습목표
  • MySQL DBMS와 Workbench를 설치하고 root 계정으로 접속할 수 있다.
  • MySQL의 주요 데이터 타입을 이해하고 용도에 맞게 선택할 수 있다.
  • Workbench에서 root 계정으로 데이터베이스를 생성하고 사용할 수 있다.
  • 테이블을 생성하고 데이터를 삽입·조회할 수 있다.
  • ER 다이어그램으로 개체와 관계를 표현하는 방법을 이해한다.
  • NOT NULL · PRIMARY KEY 제약 조건의 의미와 필요성을 설명할 수 있다.
  • 제약 조건 위반 시 발생하는 오류(1062, 1364)를 이해한다.

📖 MySQL DBMS 설치

웹 애플리케이션에서 데이터베이스와의 연동은 필수적인 작업입니다. 이런 상호작용을 위해서는 데이터베이스 관리 시스템(DBMS)이 설치되어야 합니다.

① 'mysql download' 검색 → MySQL Community Downloads ② 8.4.8 LTS 버전 선택 → 설치 ③ 설치 정보 입력 - 사용자 : root - 비밀번호 : pw1234 - 포트 : 3306
💡 정리 MySQL Workbench(워크벤치)는 MySQL 데이터베이스를 시각적으로 관리하고 설계할 수 있도록 돕는 통합 개발 환경(IDE)입니다. 설치 후 root 계정으로 접속합니다.

📖 MySQL 데이터 타입(Data Type)

데이터 타입설명
CHAR고정길이 문자, 최대 255byte, 디폴트값은 1byte
VARCHAR가변길이 문자, 최대 65536byte, 디폴트값은 1byte
INT가변 숫자, 십진수 기준 최대 220byte
TEXT가변길이 문자, 최대 65536byte, 디폴트값은 1byte
DATE날짜 — 연, 월, 일
TIMESTAMP날짜 — 연, 월, 일, 시, 분, 초, 밀리초

사각형은 개체(엔티티), 마름모는 관계, 타원은 속성(칼럼)을 나타냅니다.

📖 제약 조건(Constraints)

테이블들은 각 속성(칼럼)에 대한 무결성을 유지하기 위한 다양한 제약 조건이 적용되어 있습니다. 제약 조건에는 NOT NULL, 기본키, 외래키, CHECK 등이 있습니다.

제약 조건설명
NOT NULL칼럼을 정의할 때 명시하면 반드시 데이터를 입력해야 한다.
칼럼명 데이터타입 NOT NULL
PRIMARY KEY (기본키)UNIQUE와 NOT NULL 속성을 동시에 가진 제약 조건. 테이블당 1개의 기본키만 생성 가능.
칼럼명 데이터타입 PRIMARY KEY 또는 PRIMARY KEY(칼럼명, ...)

create table employee(

);

-- 사원 추가

*/

-- 사원 전체 검색

-- 사원 1명 검색
select * from employee where id = 'e1002';

-- 테이블 삭제
drop table employee;

Workbench SQL Editor

  id varchar(5) primary key,
  name varchar(20) not null,

insert into employee(id, name, salary) values ('e1001', '김대리', 3500000);

-- 사원 검색

-- 아이디가 'e1001'인 사원의 이름과 급여 검색

✏️ 실습문제

실습 6-3. 오류 코드 해석하기

기본키가 id인 employee 테이블에서 Error Code: 1062. Duplicate entry 'e1002'와 Error Code: 1364. Field 'name' doesn't have a default value가 각각 왜 발생하는지 설명하세요.

정답 보기
  • 1062: 이미 존재하는 기본키 값('e1002')을 또 삽입하려 해서 발생합니다. PRIMARY KEY는 UNIQUE 속성을 가지므로 값이 중복될 수 없습니다.
  • 1364: name 컬럼이 NOT NULL인데 값을 넣지 않아 발생합니다. 기본값도 없으므로 반드시 값을 입력해야 합니다.

📖 왜 axios와 CORS가 필요한가

리액트 클라이언트와 Express 서버는 서로 다른 출처(origin, 포트)에서 실행됩니다. 브라우저는 보안 정책상 다른 출처로의 요청을 기본적으로 차단하므로, 서버가 CORS로 특정 출처를 허용해 주어야 합니다. 클라이언트 쪽은 axios로 HTTP 요청을 보냅니다.

리액트(client, :5137) → axios 요청 → Express 서버(:8000) → CORS 허용 → MySQL 조회 → JSON 응답
💡 예제 — 클라이언트 측 통신 (axios)
터미널 (client) 
npm install axios
api 폴더 하위에 api.js 작성 
// baseURL 설정: API 서버의 기본 URL을 지정
const api = axios.create({
  baseURL: 'http://localhost:8000',
})
💡 예제 — 서버 측 통신 (cors())
터미널 (server) 
npm install cors
index.js (server) 
// CORS 설정 - 리액트와 통신하기 위해 필요
app.use(cors({
  origin: 'http://localhost:5137',
}));
💡 정리 서버의 origin에는 클라이언트(리액트)의 주소를, 클라이언트 axios의 baseURL에는 서버의 주소를 지정합니다. 방향이 서로 반대라는 점에 주의하세요.

src/api/api.jsx

// axios 인스턴스 생성

🎯 학습목표
  • useEffect + api.get으로 마운트 시 상품 목록을 불러온다.
  • 응답 데이터를 useState에 저장하고 map으로 표에 렌더링한다.
  • dayjs로 날짜를 포맷하고, Link로 상세 페이지로 이동한다.
  • 객체 형태의 formData 상태와 공통 handleInputChange로 여러 입력을 관리한다.
  • api.post로 새 상품을 등록하고, 성공 시 목록 페이지로 이동한다.
  • e.preventDefault()로 폼 기본 제출(새로고침)을 막는다.
  • useParams로 URL의 :id를 읽어 특정 상품을 조회한다.
  • 조건부 렌더링으로 로딩 상태와 데이터 표시를 구분한다.
  • 수정·삭제·목록 버튼으로 다른 페이지로 이동하는 흐름을 구성한다.
  • window.confirm으로 삭제 전 사용자 확인을 받는다.
  • api.delete로 상품을 삭제하고 목록으로 이동한다.
  • 삭제 성공/실패 시 적절한 안내(alert)와 에러 처리를 한다.
  • 마운트 시 기존 상품 정보를 조회해 폼의 초기값으로 채운다.
  • api.put으로 수정 내용을 서버에 반영한다.
  • 서버 응답의 product_name을 폼의 productName에 매핑하는 차이를 이해한다.

📖 데이터 흐름 (READ)

컴포넌트 마운트 → useEffect 실행 → api.get('/products') → then(setProducts) → 표 렌더링

api.get('/products')로 서버에서 상품 배열을 받아 products 상태에 저장하고, products.map()으로 각 행을 그립니다. 실패 시 catch에서 에러를 콘솔에 출력합니다.

💡 예제 — 상품 목록 조회 및 렌더링
src/products/ProductList.jsx 
import api from '../api/api'
import { useState, useEffect } from 'react'
import { Link } from 'react-router-dom'
import dayjs from 'dayjs'


const ProductList = () => {
  const [products, setProducts] = useState([])

  useEffect(() => {
    // 상품 목록 조회 API 호출
    api.get('/products')
      .then(response => {
        setProducts(response.data) // 응답 데이터로 상태 업데이트
      })
      .catch(error => {
        console.error('상품 목록 조회 에러:', error)
      })
  }, [])

  return (
    <div className="product-list">
      <h2>상품 리스트</h2>
      <table>
        <thead>
          <tr>
            <th>번호</th>
            <th>상품명</th>
            <th>가격</th>
            <th>등록일</th>
          </tr>
        </thead>
        <tbody>
          {products.map(product => (
            <tr key={product.id}>
              <td>{product.id}</td>
              <td>
                <Link to={`/products/${product.id}`}>{product.product_name}</Link>
              </td>
              <td>{product.price}원</td>
              <td>{dayjs(product.created_at).format('YYYY-MM-DD HH:mm:ss')}</td>
            </tr>
          ))}
        </tbody>
      </table>
      <div className='btn-add'>
        <Link to="/products/new"><button>상품 등록</button></Link>
      </div>
    </div>
  )
}

export default ProductList

📖 하나의 상태 객체로 폼 관리

입력마다 개별 useState를 두는 대신, { productName, price } 하나의 객체를 formData로 관리합니다. 입력의 name 속성을 키로 사용해 [name]: value 계산 속성으로 한 핸들러가 모든 입력을 갱신합니다.

입력 변경 → handleInputChange → setFormData({...formData, [name]: value}) → 제출 → api.post('/products', formData) → navigate('/products')
💡 예제 — 상태와 핸들러
src/products/AddProduct.jsx 
import { useState } from 'react'
import { useNavigate } from 'react-router-dom'
import api from '../api/api'

const AddProduct = () => {
  // const [productName, setProductName] = useState('')
  // const [price, setPrice] = useState('')
  const [formData, setFormData] = useState({
    productName: '',
    price: ''
  })
  // formData에서 productName과 price 추출
  const { productName, price } = formData
  const navigate = useNavigate();

  // 입력값 변경 핸들러
  const handleInputChange = (e) => {
    // 입력 필드의 name과 value 추출
    const { name, value } = e.target
    // formData의 해당 필드 업데이트
    setFormData({ ...formData, [name]: value })
  }
💡 예제 — 등록/취소 처리
src/products/AddProduct.jsx 
  const handleSubmit = (e) => {
    e.preventDefault() // 폼 제출 시 페이지 새로고침 방지
    // 상품 등록 API 호출
    api.post('/products', formData)
      .then(response => {
        alert('상품이 성공적으로 등록되었습니다.')
        navigate('/products') // 상품 목록 페이지로 이동
      })
      .catch(error => {
        console.error('상품 등록 에러:', error)
        alert('상품 등록 중 오류가 발생했습니다.')
      })
  }
  // 취소 버튼 클릭시 입력상자 초기화
  const handleCancel = () => {
    setFormData({
      productName: '',
      price: ''
    })
  }

📖 상세 조회 흐름

useParams()로 경로의 id를 얻어 api.get(`/products/${id}`)로 단일 상품을 조회합니다. 아직 데이터가 없으면(product가 null) "불러오는 중" 문구를, 도착하면 상세 정보를 보여줍니다. 의존성 배열에 [id]를 넣어 id가 바뀌면 다시 조회합니다.

💡 예제 — 상품 상세 조회 및 표시
src/products/ProductInfo.jsx 
const ProductInfo = () => {
  const {id} = useParams()
  const navigate = useNavigate()
  const [product, setProduct] = useState(null)

  useEffect(() => {
    // 상품 상세 조회 API 호출
    api.get(`/products/${id}`)
      .then(response => {
        setProduct(response.data) // 응답 데이터로 상태 업데이트
      })
      .catch(error => {
        console.error('상품 상세 조회 에러:', error)
      })
  }, [id])

  return (
    <div className='product-info'>
      <h2>상품 정보</h2>
      {product ? (
        <div className='product-details'>
          <p>상품 ID: {product.id}</p>
          <p>상품명: {product.product_name}</p>
          <p>가격: {product.price}원</p>
          <p>등록일: {dayjs(product.created_at).format('YYYY-MM-DD HH:mm:ss')}</p>
        </div>
      ) : (
        <p>상품 정보를 불러오는 중입니다...</p>
      )}

      <div className='edit-buttons'>
        <button onClick={() => navigate(`/products/update/${id}`)}>수정</button>
        <button onClick={() => {
          if (window.confirm('정말 삭제하시겠습니까?')) {
            api.delete(`/products/${id}`)
              .then(() => {
                alert('상품이 삭제되었습니다.')
                navigate('/products')
              })
              .catch(error => {
                console.error('상품 삭제 에러:', error)
                alert('상품 삭제 중 오류가 발생했습니다.')
              })
          }
        }}>삭제</button>
        <button onClick={() => navigate('/products')}>목록</button>
      </div>
    </div>
  )
}

export default ProductInfo

📖 수정 흐름

마운트 → api.get으로 기존 값 조회 → setFormData로 폼 초기화 → 사용자 편집 → 제출 → api.put(`/products/${id}`, formData) → navigate(`/products/${id}`)

등록(CREATE)과 달리 수정 화면은 기존 값을 먼저 불러와 입력창을 채운 뒤 편집하게 합니다. 제출은 PUT 메서드를 사용하고, 성공 시 방금 수정한 상세 페이지로 돌아갑니다.

💡 예제 — 기존 값 불러오기

const UpdateProduct = () => {
  const { id } = useParams()
  const [formData, setFormData] = useState({
    productName: '',
    price: ''
  })
  const { productName, price } = formData
  const navigate = useNavigate()

  // 컴포넌트가 마운트될 때 상품 정보를 조회하여 폼에 초기값 설정
  useEffect(() => {
    api.get(`/products/${id}`)
      .then(response => {
        setFormData({
          productName: response.data.product_name,
          price: response.data.price
        })
      })
      .catch(error => {
        console.error('상품 조회 에러:', error)
      })
  }, [id])

      })
  }

  const handleCancel = () => {
    setFormData({
      productName: '',
      price: ''

  }
