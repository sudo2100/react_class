1 Express 프레임워크 소개

🎯 학습목표
  • Express 프레임워크가 무엇인지, 어디에 쓰이는지 이해한다.
  • Express로 만드는 가장 기본적인 서버 코드의 형태를 파악한다.

📖 Express 프레임워크란?

Express는 Node.js 기반에서 동작하는 웹 서버 프레임워크로, 서버 개발을 쉽고 빠르게 할 수 있도록 도와주는 가볍고 유연한 백엔드 도구입니다.

주로 다음과 같은 곳에서 사용합니다.

  • REST API 서버 — 데이터를 주고받는 API 제공
  • 프론트엔드(React 등) 백엔드 — SPA에 데이터를 공급하는 서버
  • 간단한 웹 서버 — 정적/동적 페이지 응답
  • 풀스택 프로젝트 — 프론트와 백엔드를 함께 구성
💡 정리 Express 공식 문서(expressjs.com)의 슬로건은 "Fast, unopinionated, minimalist web framework for Node.js"입니다. 설치는 npm install express --save 로 합니다.
💡 예제 — Express 공식 예제(가장 기본 형태)
index.js 
const express = require('express')
const app = express()
const port = 3000

app.get('/', (req, res) => {
  res.send('Hello World!')
})

app.listen(port, () => {
  console.log(`Example app listening on port ${port}`)
})

4 REST API 만들기 — 상품 목록 · 등록

🎯 학습목표
  • REST API와 HTTP 메서드(GET · POST · PUT · DELETE)의 역할을 이해한다.
  • app.get으로 상품 목록을 JSON으로 응답하는 API를 만들 수 있다.
  • express.json() 미들웨어로 요청 본문(req.body)을 파싱할 수 있다.

📖 RESTful API와 HTTP 메서드

메서드의미Express 코드
GET조회app.get(url) → res.json(data)
POST생성app.post(url) → req.body(data)
PUT수정app.put(url)
DELETE삭제app.delete(url)
💡 정리 POST 요청처럼 요청 본문(body)에 담긴 JSON 데이터를 req.body로 읽으려면 app.use(express.json()) 미들웨어를 반드시 등록해야 합니다.
💡 예제 — 상품 목록 API (GET)
index.js 
// 상품 목록 API
app.get('/products', (req, res) => {
  const products = [
    { id: 1, name: '무선마우스', price: 30000 },
    { id: 2, name: '유선키보드', price: 20000 },
    { id: 3, name: '웹캠', price: 40000 },
  ];
  res.json(products); // JSON 형태로 응답 보내기
});
브라우저 출력

http://localhost:8000/products (pretty print 적용):

[
  { "id": 1, "name": "무선마우스", "price": 30000 },
  { "id": 2, "name": "유선키보드", "price": 20000 },
  { "id": 3, "name": "웹캠", "price": 40000 }

💡 예제 — 상품 등록 API (POST) + JSON 미들웨어
index.js 
// JSON 요청 본문 파싱 미들웨어
app.use(express.json());

// 상품 등록 API
app.post('/products', (req, res) => {
  // postman 테스트 도구 사용해서 body에 json 형태로 데이터 전달
  console.log(req.body); //{ id: 4, name: '모니터', price: 120000 }
  res.send('상품이 등록되었습니다.');
});

5 Postman으로 API 테스트하기 + 전체 코드

🎯 학습목표
  • Postman을 설치하고 Workspace · Collection을 구성할 수 있다.
  • POST 요청의 Body에 JSON을 담아 API를 테스트할 수 있다.
  • 미들웨어 · 로깅 · GET · POST를 포함한 전체 서버 코드를 이해한다.

📖 Postman — REST API 테스트 도구

브라우저는 주소창으로 GET 요청만 편하게 보낼 수 있습니다. POST/PUT/DELETE처럼 본문이 필요한 요청을 테스트하려면 Postman 같은 테스트 도구가 필요합니다.

Postman 설치 → My Workspace > COLLECTION > 추가 → 요청(Method + URL) 생성 → Body > raw > JSON 선택 후 데이터 입력 → Send
💡 예제 — POST 요청 보내기 (Postman)
Postman → POST http://localhost:8000/products → Body(raw, JSON) 
{
  "id": 4,
  "name": "모니터",
  "price": 120000
}
브라우저 출력

응답 (200 OK):

상품이 등록되었습니다.

💡 예제 — 전체 코드 (미들웨어 · 로깅 · GET · POST)
index.js 
import express from 'express';

const app = express();
const PORT = 8000;

// 요청 본문(JSON/form-data)을 파싱하기 위한 미들웨어
app.use(express.json());

// 모든 요청 로깅 - 요청 URL을 콘솔에 출력
app.use((req, res, next) => {
  console.log(`${req.url}`);
  next();
});

// 웹 브라우저 요청
// 루트 경로에 대한 GET 요청 처리 - http://localhost:8000/
app.get('/', (req, res) => {
  res.send('Hello Express!'); // 클라이언트에게 응답(문자열 전송)
});

// restful API - 상품 목록, 상품 등록
// http 메서드 - get, post, put, delete
// get 요청 - http://localhost:8000/products
app.get('/products', (req, res) => {
  const products = [
    { id: 1, name: '노트북', price: 1000000 },
    { id: 2, name: '모니터', price: 300000 },
  ];
  res.json(products); // 클라이언트에게 JSON 형식으로 응답
});

// post 요청 - http://localhost:8000/products
// postman 도구로 테스트 가능
app.post('/products', (req, res) => {
  console.log('요청 본문:', req.body);
  res.send('상품 등록 완료');
});

//서버 실행
app.listen(PORT, () => {
  console.log(`서버 실행중.. 포트: ${PORT}`);
});

6 SQL 기초 — DDL · DML · DCL

🎯 학습목표
  • SQL의 개념과 DDL · DML · DCL 세 가지 분류를 구분할 수 있다.
  • 테이블 생성/삭제/변경, 데이터 삽입/조회/수정/삭제 문법을 익힌다.
  • 트랜잭션(commit/rollback)과 권한(grant/revoke) 명령을 이해한다.

📖 SQL(Structured Query Language)이란?

'에스큐엘' 또는 '시퀄'이라 부르며, 사용자와 데이터베이스 시스템 간에 의사 소통을 하기 위한 언어입니다. 사용자가 SQL로 데이터의 검색·조작·정의 등을 요구하면, DB 시스템이 필요한 데이터를 가져와 결과를 알려줍니다.

구분개념
DDL (Data Definition Language) — 데이터 정의어테이블을 포함한 여러 객체를 생성·수정·삭제하는 명령어
DML (Data Manipulation Language) — 데이터 조작어데이터를 저장·검색·수정·삭제하는 명령어
DCL (Data Control Language) — 데이터 제어어데이터 사용 권한과 관련된 명령어
💡 예제 — DDL (데이터 정의어)
SQL 
-- 테이블 생성(만들기)
create table 테이블이름(
  name char(10),
  age int
);

-- 테이블 삭제
drop table 테이블이름;
truncate table 테이블이름;  -- 모든 데이터 삭제(테이블은 유지)

-- 테이블 변경
alter table 테이블이름 add 칼럼추가;
💡 예제 — DML (데이터 조작어)
SQL 
-- 자료 삽입(insert)
insert into 테이블이름(칼럼명) values (값1, 값2);

-- 자료 조회(select)
select 칼럼명 from 테이블이름;

-- 자료 수정(update)
update 테이블이름 set 칼럼명 = '변경내용' where 칼럼명;

-- 자료 삭제(delete)
delete from 테이블이름;
💡 예제 — DCL (데이터 제어어)
SQL 
-- 커밋과 롤백 (트랜잭션 = 작은 업무 단위)
commit;    -- 트랜잭션 완료
rollback;  -- 변경사항을 취소하고 원래대로 복구

-- 권한 부여와 해제
grant ...;   -- DB 권한을 부여
revoke ...;  -- DB 권한을 해제

7 MySQL · Workbench 설치와 데이터 타입

  • MySQL의 주요 데이터 타입을 이해하고 용도에 맞게 선택할 수 있다.

📖 MySQL DBMS 설치

웹 애플리케이션에서 데이터베이스와의 연동은 필수적인 작업입니다. 이런 상호작용을 위해서는 데이터베이스 관리 시스템(DBMS)이 설치되어야 합니다.

① 'mysql download' 검색 → MySQL Community Downloads ② 8.4.8 LTS 버전 선택 → 설치 ③ 설치 정보 입력 - 사용자 : root - 비밀번호 : pw1234 - 포트 : 3306
💡 정리 MySQL Workbench(워크벤치)는 MySQL 데이터베이스를 시각적으로 관리하고 설계할 수 있도록 돕는 통합 개발 환경(IDE)입니다. 설치 후 root 계정으로 접속합니다.

📖 MySQL 데이터 타입(Data Type)

데이터 타입설명
CHAR고정길이 문자, 최대 255byte, 디폴트값은 1byte
VARCHAR가변길이 문자, 최대 65536byte, 디폴트값은 1byte
INT가변 숫자, 십진수 기준 최대 220byte
TEXT가변길이 문자, 최대 65536byte, 디폴트값은 1byte
DATE날짜 — 연, 월, 일

9 RDBMS와 제약 조건 — ER 다이어그램 · employee

🎯 학습목표
  • ER 다이어그램으로 개체와 관계를 표현하는 방법을 이해한다.
  • NOT NULL · PRIMARY KEY 제약 조건의 의미와 필요성을 설명할 수 있다.
  • 제약 조건 위반 시 발생하는 오류(1062, 1364)를 이해한다.

📖 ER 다이어그램 — 부서와 사원의 개체 관계도

[부서] ── <소속> ── [사원] │ │ 부서번호 부서이름 위치 사원번호 사원이름 나이

사각형은 개체(엔티티), 마름모는 관계, 타원은 속성(칼럼)을 나타냅니다.

📖 제약 조건(Constraints)

테이블들은 각 속성(칼럼)에 대한 무결성을 유지하기 위한 다양한 제약 조건이 적용되어 있습니다. 제약 조건에는 NOT NULL, 기본키, 외래키, CHECK 등이 있습니다.

제약 조건설명
NOT NULL칼럼을 정의할 때 명시하면 반드시 데이터를 입력해야 한다.
칼럼명 데이터타입 NOT NULL
PRIMARY KEY (기본키)UNIQUE와 NOT NULL 속성을 동시에 가진 제약 조건. 테이블당 1개의 기본키만 생성 가능.
칼럼명 데이터타입 PRIMARY KEY 또는 PRIMARY KEY(칼럼명, ...)

실습 9-1. 오류 코드 해석하기

기본키가 id인 employee 테이블에서 Error Code: 1062. Duplicate entry 'e1002'와 Error Code: 1364. Field 'name' doesn't have a default value가 각각 왜 발생하는지 설명하세요.

12 MVC 패턴으로 서버 구조화하기

🎯 학습목표
  • MVC 패턴의 세 가지 역할(Model · View · Controller)을 이해한다.
  • Express 프로젝트에서 파일별 역할을 분리하는 방법을 파악한다.
  • MVC 계층별 코드 작성 순서를 이해한다.

📖 1. MVC 패턴이란?

MVC 패턴은 애플리케이션을 다음 3가지 역할로 나누어 관리하는 구조입니다.

  • Model: 데이터 처리, 데이터베이스 연결, 비즈니스 로직 담당
  • View: 사용자에게 보여주는 화면 또는 응답 결과 담당
  • Controller: 클라이언트 요청을 받아서 처리 흐름을 연결하는 담당

📖 2. Express MVC 프로젝트에서의 역할 분리

프로젝트 이름은 react-server이며(개발 환경: node.js + express + MySQL/Workbench), 각 파일의 역할은 다음과 같습니다.

파일역할
index.js서버를 실행하고 라우트를 연결하는 진입점
route/productRoute.jsURL 경로와 컨트롤러를 연결
controller/productController.js요청을 받아서 서비스 계층으로 전달
service/productService.js비즈니스 로직 처리
repository/productRepository.js데이터베이스 접근 및 쿼리 처리
config/database.js데이터베이스 연결 설정
💡 정리 MVC 코드 작성 순서는 보통 config → repository → service → controller → route → index 순으로, 데이터 접근 계층부터 진입점 방향으로 쌓아 올립니다.
