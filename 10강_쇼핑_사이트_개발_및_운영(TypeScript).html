1 강의 개요와 시작 상태 확인

🎯 학습목표
  • 컴포넌트에 넘기는 값(props)에 타입을 붙일 수 있다.

3 데이터 · 타입 파일 분리와 타입 설계

🎯 학습목표
  • 데이터 파일을 .js · .json · .ts 중 무엇으로 둘지 판단할 수 있다.
  • as 타입 단언이 검사를 끄는 것에 가깝다는 점을 이해한다.
  • 여러 파일이 쓰는 타입을 별도 파일로 분리해 의존 관계를 정리할 수 있다.
  • import type의 의미를 설명할 수 있다.
  • Omit으로 등록용 파생 타입을 만들 수 있다.

① 데이터 파일 분리 (.js → .ts)

상품 데이터를 컴포넌트 밖 src/datas/ 폴더로 옮깁니다. 이때 파일 형식을 무엇으로 할지 고민해 봅니다.

📖 .json vs .ts 비교

.ts.json
타입 검사항목을 빠뜨리거나 잘못 적으면 바로 오류값만 보고 타입을 추측, 오타를 못 잡음
주석, 마지막 쉼표가능불가능
어울리는 상황코드 안에서 직접 가져다 쓸 때fetch로 서버처럼 불러올 때 (public/products.json)

TypeScript 프로젝트에서 코드로 직접 가져다 쓴다면 .ts 가 유리합니다.

💡 정리 .json을 가져와서 as ProductProp[]로 타입을 붙이면 오류는 사라지지만, 실제로 데이터가 규칙에 맞는지는 검사하지 않습니다. 검사를 끄는 것에 가깝습니다.

② 타입 파일 분리

지금은 상품 타입이 ProductList.tsx 안에 있어서, 데이터 파일과 카드 컴포넌트가 목록 컴포넌트에 의존하게 됩니다.

ProductCard ──→ ProductList (타입 때문에) products.ts ──→ ProductList (타입 때문에)

타입을 별도 파일로 빼면 모두가 한 곳만 바라보게 됩니다.

ProductCard ──→ types/product.ts ProductList ──→ types/product.ts products.ts ──→ types/product.ts

import type을 쓰면 타입만 가져온다는 뜻이 분명해지고, 빌드 결과에서도 빠집니다.

import type { Product } from '../types/product';

export type Category = "마우스" | "키보드" | "모니터" | "주변기기";

📖 등록용 타입: Omit

type NewProduct = Omit<Product, 'id'>;
// { pName: string; category: Category; price: number; description: string; }

Product를 고치면 NewProduct도 자동으로 따라 바뀝니다.

4 Context로 상품 상태 공유

🎯 학습목표
  • 여러 화면이 함께 쓰는 상태가 왜 필요한지 설명할 수 있다.
  • Context · Provider · 커스텀 훅을 파일로 나눠 상품 상태를 공유할 수 있다.
  • 이전 값을 받는 setState와 새 배열로 불변성을 지킬 수 있다.

📖 왜 필요할까?

지금 상품 목록은 파일에서 가져와 읽기만 하는 고정된 배열입니다. 상품 등록 화면에서 새 상품을 만들어도 담아 둘 곳이 없고, 목록 화면에 반영할 방법도 없습니다.

[상품 등록 화면] ──추가──→ ??? ←──읽기── [상품 목록 화면]

여러 화면이 같은 데이터를 함께 쓰려면 공용 저장소가 필요합니다. React의 Context API를 사용합니다.

💡 예제 — ① Context와 꺼내 쓰는 함수 만들기
src/context/ProductContext.ts 
import type { Product, NewProduct } from "../types/product";
import { createContext, useContext } from "react";

// 상품 컨텍스트 타입 정의
interface ProductContextType {
  products: Product[];
  addProduct: (newProduct: NewProduct) => void;
  removeProduct: (productId: number) => void;
  updateProduct: (updatedProduct: Product) => void;
}

// 상품 컨텍스트 생성
export const ProductContext = createContext<ProductContextType | null>(null);

// 상품 컨텍스트 커스텀 훅
export const useProduct = () => {
  const context = useContext(ProductContext);
  if (!context) {
    throw new Error("useProduct는 ProductProvider 내부에서만 사용 가능합니다.");
  }
  return context;
};
  • 처음 값을 null로 두고, useProduct 안에서 null인지 확인합니다.
  • 덕분에 사용하는 쪽에서는 매번 null 검사를 하지 않아도 됩니다.
  • Provider 밖에서 실수로 쓰면 어디가 잘못됐는지 알려 주는 오류가 납니다.

💡 예제 — ② 저장소 컴포넌트(Provider) 만들기
src/context/ProductProvider.tsx 
import React, { useState} from "react";
import type { Product, NewProduct } from "../types/product";
import { initialProducts } from "../datas/products";
import { ProductContext } from "./ProductContext";

const ProductProvider = ({ children }: { children: React.ReactNode }) => {
  // 상품 상태 관리
  const [products, setProducts] = useState<Product[]>(initialProducts);

  // 상품 추가 함수
  const addProduct = (newProduct: NewProduct) => {
    // 새로운 상품에 고유 ID를 부여하고 상태 업데이트
    const product: Product = { ...newProduct, id: Date.now() };
    setProducts([...products, product]);
  };

  // 상품 삭제 함수
  const removeProduct = (productId: number) => {
    // 삭제할 상품만 빼고 새 배열로 상태 업데이트
    setProducts(products.filter((product) => product.id !== productId));
  };

  // 상품 수정 함수
  const updateProduct = (updatedProduct: Product) => {
    // id가 같은 상품만 수정된 상품으로 바꾸고 상태 업데이트
    setProducts(products.map((product) =>
      product.id === updatedProduct.id ? updatedProduct : product
    ));
  };

  return (
    <ProductContext.Provider value={{ products, addProduct, removeProduct, updateProduct }}>
      {children}
    </ProductContext.Provider>
  );
}

export default ProductProvider;
  • useState<Product[]>(initialProducts) — 데이터 파일의 상품을 처음 값으로만 쓰고, 이후 상품 목록은 이 상태(products)가 관리합니다. 그래서 데이터 파일의 이름도 initialProducts로 바꿉니다.
  • addProduct(newProduct: NewProduct) — 등록 화면에서 id가 없는 상품(NewProduct)을 받습니다.
  • { ...newProduct, id: Date.now() } — 입력받은 값을 펼쳐 복사하고 id를 붙여 완성된 Product를 만듭니다. Date.now()는 현재 시각을 밀리초 숫자로 돌려주므로, 연습용 고유 번호로 쓸 수 있습니다.
  • const product: Product처럼 타입을 적어 두면, 항목이 빠졌을 때 TypeScript가 바로 알려 줍니다.
  • setProducts([...products, product]) — 기존 배열을 고치지 않고 새 배열을 만들어야 React가 변화를 알아채고 화면을 다시 그립니다.
  • removeProduct(productId) — filter로 삭제할 상품만 뺀 새 배열을 만듭니다.
  • updateProduct(updatedProduct) — map으로 id가 같은 상품만 수정된 상품으로 바꾼 새 배열을 만듭니다.
  • value={{ products, addProduct, removeProduct, updateProduct }} — ①의 ProductContextType에 적은 네 가지를 모두 넘겨야 타입 오류가 나지 않습니다. Provider 안의 모든 컴포넌트가 useProduct()로 꺼내 쓸 수 있습니다.
💡 왜 파일을 두 개로 나눴나요? Vite의 빠른 새로고침(Fast Refresh)은 컴포넌트만 내보내는 파일에서 가장 잘 동작합니다. 컴포넌트(ProductProvider)와 컴포넌트가 아닌 것(ProductContext, useProduct)을 나눠 두면 저장할 때 화면 상태가 유지됩니다.

💡 예제 — ③ 등록 화면에서 addProduct 쓰기 (상품 등록)
src/products/AddProduct.tsx 
import type { Category } from "../types/product";
import type { ProductForm } from "../types/product";
import { useProduct } from "../context/ProductContext";
import { useState } from "react";
import { useNavigate } from "react-router-dom";

// 초기 폼 데이터
const initialForm: ProductForm = {
  pName: "",
  category: "마우스",
  price: 0,
  description: "",
};

const AddProduct = () => {
  const {addProduct} = useProduct();
  const [form, setForm] = useState<ProductForm>(initialForm);
  const [error, setError] = useState<string | null>(null);

  // 폼 데이터 구조 분해 할당
  const {pName, category, price, description} = form;
  const navigate = useNavigate();

  // 입력값 변경 핸들러
  const handleChange = (
    e: React.ChangeEvent<HTMLInputElement | HTMLSelectElement | HTMLTextAreaElement>) => {
    const { name, value } = e.target;
    setForm({
      ...form,
      [name]: value
    });
  };

  // 폼 제출 핸들러
  const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    // 유효성 검사
    if(!pName.trim()){
      setError("상품명을 입력해주세요.");
      return;
    }
    if(!price || price <= 0){
      setError("가격을 올바르게 입력해주세요.");
      return;
    }
    if(!description.trim()){
      setError("설명을 입력해주세요.");
      return;
    }

    // 상품 추가
    addProduct({
      pName, 
      category, 
      price: Number(price), 
      description
    });
    alert("상품이 등록되었습니다.");
    // 상품 목록 페이지로 이동
    navigate('/');
  }

  // 폼 초기화 핸들러
  const handleCancel = () => {
    setForm(initialForm);
    setError(null);
  };

  return (
    <div className="product-add"> 
      <h2>상품 등록</h2>
      <form onSubmit={handleSubmit}>
        <div>
          <label htmlFor="pName">상품명:</label>
          <input
            type="text"
            id="pName"
            name="pName"
            value={pName}
            onChange={handleChange}
          />
        </div>
        <div>
          <label htmlFor="category">카테고리:</label>
          <select
            id="category"
            name="category"
            value={category}
            onChange={handleChange}
          >
            <option value="마우스">마우스</option>
            <option value="키보드">키보드</option>
            <option value="모니터">모니터</option>
            <option value="주변기기">주변기기</option>
          </select>
        </div>
        <div>
          <label htmlFor="price">가격:</label>
          <input
            type="number"
            id="price"
            name="price"
            value={price}
            onChange={handleChange}
          />
        </div>
        <div>
          <label htmlFor="description">설명:</label>
          <textarea
            id="description"
            name="description"
            value={description}
            onChange={handleChange}
          />
        </div>
        {error && <p className="product-add_error">{error}</p>}
        <div className="product-add_buttons">
          <button type="submit">등록</button>
          <button type="button" onClick={handleCancel}>취소</button>
        </div>
      </form>
    </div>
  )
}

export default AddProduct
  • 폼 전용 타입: 입력창 값은 type="number"라도 항상 문자열이므로 price를 string으로 받고, 등록할 때 숫자로 바꿉니다.
  • initialForm을 컴포넌트 밖에 두면 렌더링할 때마다 새로 만들지 않습니다. 카테고리 처음 값은 CATEGORIES[0]으로 둡니다.
  • 핸들러 하나: [name]: value는 변수 값을 키로 쓰는 문법입니다. 입력창의 name 속성을 ProductForm의 키와 똑같이 적어야 동작합니다.
  • input, textarea, select에서 함께 쓰므로 이벤트 타입을 |로 묶습니다.
  • e.preventDefault()로 제출 시 새로고침을 막습니다. 새로고침되면 메모리에 있던 상품이 모두 사라집니다.
  • Number('')는 0, Number('abc')는 NaN이므로 비어 있는지와 정수인지를 함께 확인하고, 걸리면 return으로 바로 끝냅니다.
  • addProduct에는 NewProduct 타입을 넘겨야 하므로, 가격을 문자열 그대로 넘기면 TypeScript가 오류를 알려 줍니다.
  • 취소 버튼은 type="button"으로 둡니다. form 안의 버튼은 기본이 submit이라 적지 않으면 취소를 눌러도 등록이 실행됩니다.
💡 정리 입력창 값은 항상 문자열이라 폼 전용 타입 ProductForm에서는 price를 string으로 두고, 등록할 때 Number(price)로 바꿔 NewProduct 모양으로 addProduct에 넘깁니다. 카테고리 선택 목록은 CATEGORIES를 그대로 map해서 만들므로, 카테고리가 늘어나도 types/product.ts 한 곳만 고치면 됩니다.

🎯 학습목표

  • 상품과 같은 구조로 CartContext, CartProvider, useCart를 만들어 장바구니 상태를 공유할 수 있다.
  • 담기 · 수량 변경 · 삭제 · 전체 비우기 기능과 합계 수량 · 금액 계산을 구현할 수 있다.
  • 다른 Context를 쓰는 Provider를 감싸는 순서를 정할 수 있다.
  • 장바구니 화면 · 상품 카드 · 상세 · 헤더에서 useCart()로 같은 장바구니 상태를 꺼내 쓸 수 있다.

📖 왜 장바구니도 Context일까?

장바구니도 여러 화면이 함께 쓰는 데이터입니다. 카드와 상세에서 담고, 헤더와 장바구니 화면에서 읽습니다.

[상품 카드] ──담기──┐ [상품 상세] ──담기──┼──→ ??? ←──읽기── [헤더 개수] [장바구니 화면]

그래서 상품의 ProductContext와 같은 방식으로 CartContext를 만듭니다.

📖 무엇을 저장할까?

상품 전체 저장번호와 수량만 저장
저장 모양{ id, pName, price, ..., quantity }{ productId, quantity }
상품 가격이 바뀌면장바구니에는 예전 가격이 남음상품 목록에서 찾으므로 바뀐 가격이 나옴
같은 정보두 곳에 있음한 곳(상품 목록)에만 있음

같은 정보를 두 곳에 두면 한쪽만 바뀌는 문제가 생기므로 번호와 수량만 저장합니다.

💡 예제 — ① 장바구니 타입
src/types/cart.ts 
// 장바구니 아이템 타입 정의
export interface CartItem {
  productId: number;  // 상품 ID
  qty: number;  // 수량(quantity)
}
💡 정리 CartItem에는 상품 번호(productId)와 수량(qty)만 저장합니다. 상품명 · 가격은 화면에 보여 줄 때 상품 목록(products)에서 번호로 찾아 씁니다. 상품 정보를 복사해 두지 않으므로, 상품 가격이나 이름이 바뀌어도 장바구니에는 항상 최신 정보가 나옵니다.
💡 예제 — ② 장바구니 Context와 꺼내 쓰는 함수
src/context/CartContext.ts 
import type { CartItem } from '../types/cart'
import { createContext, useContext } from 'react'

// 장바구니 컨텍스트 타입 정의
interface CartContextType {
  cartItems: CartItem[];  // 장바구니 아이템 배열
  addToCart: (productId: number, qty: number) => void; 
  updateQuantity: (productId: number, qty: number) => void;
  removeFromCart: (productId: number) => void;
  totalQuantity: number;
  totalPrice: number;
  clearCart: () => void;
}

// 장바구니 컨텍스트 생성
export const CartContext = createContext<CartContextType | null>(null);

// 장바구니 컨텍스트 커스텀 훅
export const useCart = () => {
  const context = useContext(CartContext);
  if (!context) {
    throw new Error('useCart는 CartProvider 내부에서만 사용 가능합니다.');
  }
  return context;
};
💡 정리 상품의 ProductContext.ts와 같은 구조입니다. 장바구니 상태(cartItems), 바꾸는 함수(addToCart, updateQuantity, removeFromCart, clearCart), 계산한 값(totalQuantity, totalPrice)을 한 타입에 모아 둡니다. addToCart(상품번호, 수량)처럼 담을 수량도 함께 넘깁니다.
💡 예제 — ③ 장바구니 저장소 컴포넌트(Provider)
src/context/CartProvider.tsx 
import React, { useState } from 'react';
import type { CartItem } from '../types/cart';
import { CartContext } from './CartContext';
import { useProduct } from './ProductContext';

const CartProvider = ({ children }: { children: React.ReactNode }) => {
  const [cartItems, setCartItems] = useState<CartItem[]>([]);
  const {products} = useProduct(); // 상품 목록 가져오기 (상품명 조회용)

  // 장바구니에 상품 추가
  const addToCart = (productId: number, qty: number) => {
    setCartItems((prevItems) => {
      // 이미 장바구니에 있는 상품인지 확인
      const existingItem = prevItems.find((item) => item.productId === productId);
      if (existingItem) {
        // 이미 장바구니에 있는 상품이면 수량 업데이트
        return prevItems.map((item) =>
          item.productId === productId
            ? { ...item, qty: item.qty + qty }
            : item
        );
      } else {
        // 새로운 상품이면 장바구니에 추가
        return [...prevItems, { productId, qty }];
      }
    });
  };

  // 장바구니에서 상품 수량 업데이트
  const updateQuantity = (productId: number, qty: number) => {
    setCartItems((prevItems) =>
      prevItems.map((item) =>
        item.productId === productId ? { ...item, qty } : item
      )
    );
  };

  // 장바구니에서 상품 제거
  const removeFromCart = (productId: number) => {
    setCartItems((prevItems) =>
      prevItems.filter((item) => item.productId !== productId)
    );
  };

  // 총 수량 계산
  const totalQuantity = cartItems.reduce((sum, item) => sum + item.qty, 0);

  // 총 가격 계산
  const totalPrice = cartItems.reduce((sum, item) => {
    // productId로 상품 정보 찾기
    const product = products.find((p) => p.id === item.productId);
    // 상품이 존재하면 가격 계산(가격 * 수량), 없으면 0 
    return sum + (product ? product.price * item.qty : 0);
  }, 0);

  // 장바구니 비우기
  const clearCart = () => {
    setCartItems([]);
  };

  return (
    <CartContext.Provider value={{ 
      cartItems, 
      addToCart, 
      updateQuantity,
      removeFromCart, 
      totalQuantity, 
      totalPrice,
      clearCart
    }}>
      {children}
    </CartContext.Provider>
  );
};

export default CartProvider;
  • 담기: find로 이미 담긴 상품인지 확인해서, 있으면 줄을 하나 더 만들지 않고 수량만 늘립니다(item.qty + qty). 없으면 { productId, qty }를 새로 추가합니다.
  • map으로 바꿀 항목만 { ...item, qty: ... } 새 객체로 만들고, 나머지는 그대로 둡니다.
  • setCartItems((prevItems) => ...)처럼 이전 값을 받아 계산하면 여러 번 연달아 담아도 안전합니다.
  • 삭제: filter로 해당 상품만 제외한 새 배열을 만듭니다. 비우기는 빈 배열로 바꿉니다.
  • 계산할 수 있는 값은 상태로 두지 않기: 총 수량 · 총 금액을 useState로 따로 두면 담을 때마다 함께 고쳐야 하고, 하나라도 빠뜨리면 숫자가 틀어집니다. cartItems에서 매번 계산하면 항상 맞는 값이 나옵니다.
  • 총 가격: 장바구니에는 가격이 없으므로 products.find로 상품을 찾아 가격 × 수량을 더합니다. 그래서 CartProvider 안에서 useProduct()를 씁니다. reduce의 마지막 0은 시작 값입니다.
💡 참고 지금 updateQuantity에는 수량 검사가 없어서 0이나 음수로도 바꿀 수 있습니다. 장바구니 화면에서 수량이 1이면 − 버튼을 disabled로 막아 두었지만, 함수에서도 if (qty < 1) return;으로 한 번 더 막으면 더 안전합니다.

💡 예제 — ⑤ 장바구니 화면
src/products/Cart.tsx 
import { useCart } from "../context/CartContext"; // 장바구니 컨텍스트 가져오기
import { useProduct } from "../context/ProductContext"; // 상품 컨텍스트 가져오기
import { Link } from "react-router-dom";

const Cart = () => {
  const { 
    cartItems, 
    updateQuantity, 
    removeFromCart,
    totalQuantity, 
    totalPrice,
    clearCart 
  } = useCart(); // 장바구니 아이템 및 통계 정보 가져오기
  const { products } = useProduct(); // 상품 목록 가져오기 (상품명 조회용)

  // 장바구니 비우기 버튼 클릭 시
  const handleClearCart = () => {
    if (window.confirm('정말로 장바구니를 비우시겠습니까?')) {
      clearCart();
    }
  };

  return (
    <section className="cart">
      <h2>장바구니</h2>
      {cartItems.length === 0 ? (
        <p className="cart_empty">장바구니가 비어 있습니다.</p>
      ) : (
        <div> 
          <ul className="cart_list">
          {cartItems.map((item) => {
            // productId로 상품 정보 찾기
            const product = products.find((p) => p.id === item.productId);
            return (
              <li key={item.productId} className="cart_item">
                <div className="cart_info">
                  <span className="cart_category">{product?.category}</span>
                  <Link to={`/product/${product?.id}`}>{product?.pName}</Link>
                </div>
                <div className="cart_quantity">
                  <button 
                    onClick={() => updateQuantity(item.productId, item.qty - 1)} 
                    disabled={item.qty <= 1}>
                    -
                  </button>
                  <span>{item.qty}</span>
                  <button 
                    onClick={() => updateQuantity(item.productId, item.qty + 1)}>
                    +
                  </button>
                </div>
                <strong className="cart_subtotal">
                  {product ? (product.price * item.qty).toLocaleString() : 0}원
                </strong>
                <button 
                  className="cart_remove"
                  onClick={() => removeFromCart(item.productId)}>
                  삭제  
                </button>
              </li>
            );
          })}
          </ul>
          <div className="cart_summary">
            <span>총 {totalQuantity}개</span>
            <strong>{totalPrice.toLocaleString()}원</strong>
          </div>
          <div className="cart_buttons">
            <button className="cart_clear" onClick={handleClearCart}>전체 비우기</button> 
            <Link to="/" className="cart_link">쇼핑 계속하기</Link>
          </div>
          <button className="cart_order">주문하기</button>
        </div>
      )}
    </section>
  )
}

export default Cart
  • cartItems.length === 0 ? (빈 화면) : (목록)처럼 삼항 연산자로 비어 있을 때와 아닐 때를 나눠 그립니다.
  • cartItems에는 번호와 수량만 있으므로, 줄마다 products.find로 상품 정보를 찾아 상품명 · 카테고리 · 소계를 보여 줍니다.
  • product?.pName의 ?.(옵셔널 체이닝)는 상품을 못 찾아 product가 undefined일 때 오류 대신 undefined를 돌려줍니다.
  • − 버튼은 수량이 1이면 disabled로 막습니다. 누를 수 없다는 것을 화면으로 보여 주는 것이 사용자에게 더 친절합니다.
  • 소계(가격 × 수량)도 저장하지 않고 화면에서 바로 계산합니다.
  • 전체 비우기는 되돌릴 수 없으므로 window.confirm으로 한 번 더 묻습니다. 주문하기 버튼은 아직 동작 없이 자리만 만들어 둡니다.

📖 ⑥ 담기 버튼과 헤더 개수 표시

어느 컴포넌트든 useCart()만 부르면 장바구니를 쓸 수 있습니다.

  product: Product;

      <p>{product.price.toLocaleString()}원</p>

        onClick={() => {
          addToCart(product.id, 1);
          alert(`${product.pName} 상품이 장바구니에 담겼습니다.`);
        }}
      >
        담기
      </button>
    </div>
  )
}

📖 생각해 볼 점 — 새로고침하면 장바구니가 비워집니다

장바구니도 상품 목록처럼 메모리에만 있습니다. localStorage에 저장하면 새로고침 후에도 남길 수 있습니다.

const [items, setItems] = useState<CartItem[]>(() => {
  const saved = localStorage.getItem('cart');
  return saved ? JSON.parse(saved) : [];
});

useEffect(() => {
  localStorage.setItem('cart', JSON.stringify(items));
}, [items]);
  • useState(() => ...)처럼 함수를 넘기면 처음 한 번만 실행됩니다. (useEffect도 import해야 합니다.)
  • 이때 상품 목록은 저장되지 않으므로 직접 등록한 상품은 새로고침 후 사라집니다. ③에서 찾을 수 없는 상품을 제외하도록 만들어 두었기 때문에 화면이 깨지지 않습니다.

📖 생각해 볼 점 — 담았다는 것을 알리는 방법

상세 화면에서는 alert로 알리지만, alert은 확인을 누를 때까지 화면 전체를 멈춥니다. 여러 개를 연달아 담는 목록 화면에는 넣지 않았고, 헤더 숫자가 바뀌는 것으로 대신합니다. 잠깐 보였다 사라지는 안내 메시지(토스트)로 바꾸는 방법도 있습니다.

📖 정리

  1. 장바구니에는 상품 전체가 아니라 번호와 수량만 저장하고, 상품 정보는 목록에서 찾는다.
  2. 이미 담긴 상품은 some으로 확인해서 새 줄 대신 수량만 늘린다.
  3. 총 수량, 총 금액, 소계처럼 계산할 수 있는 값은 상태로 두지 않는다.
  4. 다른 Context를 쓰는 Provider는 그 Context의 Provider 안쪽에 둔다.
  5. 같은 Context를 보는 컴포넌트들은 서로 몰라도 함께 바뀐다.

7 회원가입, 로그인

🎯 학습목표
  • 유니온 타입과 Omit · Pick으로 회원 · 가입 폼 · 로그인 폼 타입을 만들 수 있다.
  • 회원 목록과 로그인한 회원을 Context로 공유할 수 있다.
  • 로그인 성공/실패를 boolean으로 돌려주고, 화면이 그 결과에 따라 메시지를 보여 줄 수 있다.
  • 입력창의 name과 폼 상태의 키를 맞춰 핸들러 하나로 여러 입력을 처리할 수 있다.
  • 로그인 여부에 따라 헤더에 다른 내용을 보여 줄 수 있다(조건부 렌더링).
  • 정규 표현식으로 회원가입 입력값을 검사하고, 아이디 중복을 처리할 수 있다.

src/types/user.ts 
// 회원 권한 타입 정의
export type Role = "user" | "admin"

// User(회원) 타입 정의
export interface User{
    id: number,
    username: string,
    password: string,
    name: string,
    email: string,
    role: Role
}

// 회원가입시 저장하는 값, id는 자동으로 부여되므로 제외
export type NewUser = Omit<User, "id">

/* 회원가입 폼 타입 정의
   User에서 id(자동 부여)와 role(일반 회원으로 고정)을 빼고,
   화면에서만 쓰는 비밀번호 확인(passwordConfirm)을 추가합니다. */
export interface SignUpForm extends Omit<User, "id" | "role">{
    passwordConfirm: string;
}

/* 로그인 폼 타입 정의
   Pick은 지정한 속성만 남깁니다.
   LoginForm은 username과 password만 가집니다. */
export type LoginForm = Pick<User, "username" | "password">

  • NewUser = Omit<User, "id"> — 저장할 때 번호(id)는 자동으로 붙이므로 뺍니다.
  • SignUpForm — User에서 id와 role을 빼고(Omit), 화면에서만 쓰는 passwordConfirm을 더합니다(extends).
  • LoginForm = Pick<User, "username" | "password"> — Pick은 Omit과 반대로 지정한 속성만 남깁니다.
  • 타입을 User 하나에서 만들어 내므로, User를 고치면 나머지 타입도 자동으로 따라 바뀝니다.

src/context/UserContext.ts 
import { createContext, useContext } from "react";
import type {User, NewUser, LoginForm} from "../types/user"

// 회원 컨텍스트 타입 정의
interface UserContextType{
    users: User[];  // 회원목록
    currentUser: User | null;  // 로그인한 회원 (로그아웃 상태면 null)
    signup: (newUser: NewUser) => void  // 회원가입
    login: (loginForm: LoginForm) => boolean  // 로그인 (성공 여부 반환)
    logout: () => void  // 로그아웃
}

// 회원 컨텍스트 생성
// null or undefined
export const UserContext = createContext<UserContextType | null>(null);

// 회원 컨텍스트 커스텀 Hook
export const useUser = () => {
    const context = useContext(UserContext);
    if(!context){
        throw new Error("useUser는 UserProvider 내부에서만 사용 가능합니다.")
    }
    return context
}
  • 상품 · 장바구니와 같은 구조입니다. 처음 값은 null로 두고 useUser 안에서 확인합니다.
  • users는 회원 목록, currentUser는 로그인한 회원입니다. currentUser가 null이면 로그아웃 상태입니다.
  • login은 LoginForm(아이디 · 비밀번호)을 받아 성공 여부를 boolean으로 돌려줍니다. 실패 메시지는 화면이 정합니다.
  • signup은 NewUser를 받아 저장만 하고 돌려주는 값이 없습니다(void). 아이디 중복 검사는 가입 화면에서 users로 먼저 합니다.
  • useUser는 Provider 밖에서 쓰면 바로 오류를 내서 실수를 빨리 알 수 있게 합니다.
💡 예제 — ④ 회원 저장소 컴포넌트(Provider)
src/context/UserProvider.tsx 
import { useState } from "react"
import { UserContext } from "./UserContext"
import type {User, NewUser, LoginForm} from "../types/user"
import { initialUsers } from "../datas/users";

// UserProvider는 회원 저장소(repository) 역할
const UserProvider = ({children} : {children: React.ReactNode}) => {
    const [users, setUsers] = useState<User[]>(initialUsers);
    const [currentUser, setCurrentUser] = useState<User | null>(null);

    // 회원가입 함수
    const signup = (newUser: NewUser) => {
        // id는 유일해야 하므로 날짜와시간으로 자동 부여
        const user: User = {...newUser, id: Date.now()};
        setUsers([...users, user])
    }

    // 로그인 함수 (성공하면 true, 실패하면 false 반환)
    const login = (loginForm: LoginForm) => {
        const found = users.find(
            (user) => user.username === loginForm.username && user.password === loginForm.password
        );
        if(!found) return false;
        setCurrentUser(found);
        return true;
    }

    // 로그아웃 함수
    const logout = () => {
        setCurrentUser(null);
    }

    return(
        <UserContext.Provider value={{
            users, 
            currentUser, 
            signup, 
            login, 
            logout
        }}>
            {children}
        </UserContext.Provider>
    )
}

export default UserProvider
  • 상태 두 개: 회원 목록(users)과 로그인한 회원(currentUser)을 따로 관리합니다.
  • 회원가입: { ...newUser, id: Date.now() }로 번호를 붙여 users에 추가합니다. 상품 등록과 같은 방식입니다.
  • 로그인: find로 아이디와 비밀번호가 모두 맞는 회원을 찾습니다. 못 찾으면 false, 찾으면 currentUser에 저장하고 true를 돌려줍니다.
  • 로그아웃: currentUser를 null로 되돌리는 것뿐입니다.
  • value에 ③ UserContextType의 다섯 가지를 모두 넘겨야 타입 오류가 나지 않습니다.

  email: ""

const EMAIL_REGEX = /^[^\s@]+@[^\s@]+\.[^\s@]+$/; 

const SignUp = () => {
  const [form, setForm] = useState<SignUpForm>(initialForm);
  const [error, setError] = useState<string | null>(null);
  const { users, signup } = useUser();
  const navigate = useNavigate();

  // 입력값 변경 핸들러

    e.preventDefault();

    // 유효성 검사

📖 정규 표현식 풀이

① 아이디: /^(?=.*[a-z])(?=.*\d)[a-z0-9]{4,12}$/

조각뜻
/ … /정규식의 시작과 끝
^문자열의 맨 앞
(?=.*[a-z])전방탐색 — 뒤쪽 어딘가에 영문 소문자가 1개 이상 있어야 함
(?=.*\d)전방탐색 — 뒤쪽 어딘가에 숫자가 1개 이상 있어야 함
[a-z0-9]영문 소문자(a~z) 또는 숫자(0~9) 중 한 글자
{4,12}바로 앞 규칙이 4번 이상 12번 이하 반복
$문자열의 맨 끝

→ 영문 소문자와 숫자만 쓰되, 둘 다 1개 이상 들어간 4~12자

전방탐색 (?=…)은 글자를 소비하지 않고 조건만 확인합니다. 그래서 두 개를 이어 써도 검사 위치는 계속 맨 앞이고, 실제 글자 종류와 길이는 뒤의 [a-z0-9]{4,12}가 검사합니다.

입력결과이유
hong1✅소문자 + 숫자 5자
abc1✅소문자 + 숫자 4자
hong❌숫자 없음
1234❌영문 없음
Hong1❌대문자 H
ab1❌3자 (너무 짧음)
💡 주의 ^와 $가 없으면 "어딘가에 규칙에 맞는 4~12자가 있기만 하면" 통과해서 hong1!!!도 통과합니다. 양 끝을 묶어야 문자열 전체를 검사합니다.

② 이메일: /^[^\s@]+@[^\s@]+\.[^\s@]+$/

조각뜻
[^\s@]공백(\s)과 @가 아닌 아무 글자 하나 — 대괄호 안 맨 앞의 ^는 "아닌 것"이라는 뜻
+바로 앞 규칙이 1번 이상 반복
@@ 글자 그대로
\.점(.) 글자 그대로 — 그냥 .은 "아무 글자"라는 뜻이라 \를 붙입니다
[^\s@]+ @ [^\s@]+ \. [^\s@]+ 아이디 @ 도메인 . 확장자 hong @ example . com
입력결과이유
hong@example.com✅
a@b.c✅각 부분이 1자 이상이면 통과
hong@example❌.확장자 없음
hong example.com❌@ 없음, 공백 있음
hong@@example.com❌@ 다음 부분에 @가 들어갈 수 없음

src/users/SignIn.tsx 
import { useState } from "react";
import { Link, useNavigate } from "react-router-dom";
import type { LoginForm } from "../types/user";
import { useUser } from "../context/UserContext";

// 로그인 폼 초기화
const initialForm: LoginForm = {
  username: "",
  password: ""
}

const SignIn = () => {
  const [form, setForm] = useState<LoginForm>(initialForm);
  const [error, setError] = useState<string | null>(null);
  const { login } = useUser();
  const navigate = useNavigate();

  // 폼에 입력된 데이터 가져오기
  const { username, password } = form;

  const handleInputChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const { name, value } = e.target;
    setForm({ ...form, [name]: value })  // 입력 데이터 저장
  }

  // 폼 제출 핸들러
  const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();

    // 유효성 검사
    if(!username.trim()){
      setError("아이디를 입력해주세요");
      return;
    }
    if(!password){
      setError("비밀번호를 입력해주세요");
      return;
    }

    // 로그인 함수 호출 (성공하면 true)
    const success = login({ username: username.trim(), password });
    if(!success){
      setError("아이디 또는 비밀번호가 올바르지 않습니다");
      return;
    }

    alert("로그인되었습니다.");
    navigate('/');  // 상품 목록으로 이동
  }

  return(
    <div className="sign-in">
      <h2>로그인</h2>
      <form onSubmit={handleSubmit}>
        <div>
          <label htmlFor="username">아이디</label>
          <input
            type="text"
            id="username"
            name="username"
            value={username}
            onChange={handleInputChange}
            placeholder="아이디를 입력하세요"
            autoComplete="username"
          />
        </div>
        <div>
          <label htmlFor="password">비밀번호</label>
          <input
            type="password"
            id="password"
            name="password"
            value={password}
            onChange={handleInputChange}
            placeholder="비밀번호를 입력하세요"
            autoComplete="current-password"
          />
        </div>
        {error && <p className="sign-in_error">{error}</p>}
        <button type="submit">로그인</button>
      </form>

      {/* 회원 가입 링크 */}
      <p className="signup-link">
        아직 계정이 없으신가요? <Link to="/signup">회원가입</Link>
      </p>
    </div>
  )
}

export default SignIn;
  • LoginForm 타입의 객체 하나(form)로 아이디와 비밀번호를 관리합니다. 입력창의 name과 키를 같게 두어 핸들러 하나로 처리합니다.
  • login({ username: username.trim(), password })처럼 객체로 넘기고, 돌려받은 true/false로 성공 · 실패를 나눕니다.
  • 아이디와 비밀번호 중 무엇이 틀렸는지는 알려 주지 않습니다. 알려 주면 어떤 아이디가 가입되어 있는지 알아낼 수 있기 때문입니다.
  • e.preventDefault()로 제출 시 새로고침을 막습니다. 새로고침되면 메모리에 있던 로그인 상태가 사라집니다.
  • 아이디만 trim() 합니다. 비밀번호는 앞뒤 공백도 비밀번호의 일부일 수 있습니다.

// match() : 찾은 문자열을 배열로 반환, 없으면 null
// 1. 문자열의 "처음"부터 패턴이 맞는지 → 패턴 앞에 ^를 붙입니다
const m = "korea".match(/^[a-z]+/);
console.log(m?.[0]); // korea

// 2. +가 없으면 1문자만 매칭 - k, + 있으면 - korea
const one = "korea".match(/^[a-z]/);
console.log(one?.[0]); // k

// 3. 문자열 "어디든" 패턴이 있으면 반환 → ^ 없이 씁니다
const s = "abc123def".match(/\d+/);
console.log(s?.[0]); // 123

// 4. 찾지 못하면 null
const n = "abc123def".match(/^\d+/);
console.log(n); // null (처음이 숫자가 아님)

// 5. $가 없을 때와 있을 때
/*
  /^[a-z]+/  - 소문자로 시작하기만 하면 됨
  /^[a-z]+$/ - 처음부터 끝까지 전부 소문자여야 함
  '$'는 입력값 유효성 검증시 필수
*/
const a = /^[a-z]+/;
const b = /^[a-z]+$/;

console.log(a.test("abc"));    // true
console.log(a.test("abc123")); // true  ← 앞부분 "abc"만 맞아도 통과
console.log(a.test("4abc"));   // false

console.log(b.test("abc"));    // true
console.log(b.test("abc123")); // false ← 뒤에 숫자가 있어서 실패
console.log(b.test("4abc"));   // false

// test() : 패턴과 일치하는지 true / false 반환
// 1. 휴대폰 번호 검사 (010-1234-5678 형식)
const phoneRegex = /^010-\d{3,4}-\d{4}$/;
console.log("1. 휴대폰 번호 검사");
console.log(phoneRegex.test("010-1234-5678")); // true
console.log(phoneRegex.test("02-123-4567")); // false

// 2. 아이디 검사 (영문 소문자 또는 숫자, 4~12자)
const userIdRegex = /^[a-z0-9]{4,12}$/
console.log("2. 아이디 검사");
console.log(userIdRegex.test("abc123")); // true
console.log(userIdRegex.test("abc")); // false (3자)

// 3. 비밀번호 검사 (영문 + 숫자 포함, 8자 이상)
// ?=.*\d - 뒤쪽 어딘가에 숫자가 1개 이상 있어야 함
const pwRegex = /^(?=.*[a-zA-Z])(?=.*\d).{8,}$/;
console.log("3. 비밀번호 검사");
console.log(pwRegex.test("abc12345")); // true
console.log(pwRegex.test("abcdefgh")); // false (숫자 없음)

// 4. 이메일 검사
/*
[^\s@]+   @   [^\s@]+   \.   [^\s@]+
 아이디   @   도메인     .    확장자
*/
const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
console.log("4. 이메일 검사");
console.log(emailRegex.test("hong@naver.com")); // true
console.log(emailRegex.test("hong@naver")); // false
// 5. 아이디 검사 (영문 소문자 + 숫자 필수 포함, 4 ~ 12자)
/* (?=.*[a-z]) - 어딘가에 소문자가 1개 이상 있어야 함
   (?=.*\d)    - 어딘가에 숫자가 1개 이상 있어야 함
   [a-z0-9]{4,12} - 소문자와 숫자로만 4 ~ 12자 */
const usernameRegex = /^(?=.*[a-z])(?=.*\d)[a-z0-9]{4,12}$/;
console.log("5. 아이디 검사 (소문자 + 숫자 필수)");
console.log(usernameRegex.test("abc123")); // true
console.log(usernameRegex.test("abcdef")); // false (숫자 없음)
console.log(usernameRegex.test("123456")); // false (소문자 없음)
console.log(usernameRegex.test("Abc123")); // false (대문자 포함)
console.log(usernameRegex.test("ab1")); // false (3자)

  • (?=.*[a-zA-Z]) — 전방탐색은 글자를 소비하지 않고 "뒤쪽 어딘가에 이 조건이 있는지"만 확인합니다. 두 개를 이어 쓰면 영문과 숫자가 모두 있어야 통과합니다. 마지막 .{8,}이 실제 길이(8자 이상)를 검사합니다.

9 관리자 페이지

🎯 학습목표

  • 관리자 페이지(/admin) 경로를 추가하고, 주소로 직접 들어와도 권한을 검사할 수 있다.
  • filter · reduce · sort로 상품 · 회원 통계를 계산할 수 있다.

📖 무엇을 만들까?

7단원에서 회원마다 role("user" | "admin")을 넣어 두었습니다. 이 값으로 관리자만 볼 수 있는 대시보드를 만듭니다. 상품과 회원 정보는 이미 Context에 있으므로 useProduct(), useUser()로 꺼내 쓰기만 하면 됩니다.

src/admin/AdminPage.tsx 
import { Link } from "react-router-dom";
import { useProduct } from "../context/ProductContext";
import { useUser } from "../context/UserContext";

const AdminPage = () => {
  const { products } = useProduct();
  const { users, currentUser } = useUser();

  // 관리자만 접근 가능 (주소창에 /admin을 직접 입력해도 권한 체크)
  if (currentUser?.role !== "admin") {
    return (
      <div className="admin-page">
        <p>관리자만 접근할 수 있습니다.</p>
        <Link to="/signin">로그인</Link>
      </div>
    );
  }

  // 관리자 수 : filter()로 role이 admin인 회원만 골라 개수 세기
  const adminCount = users.filter((user) => user.role === "admin").length;

  // 상품 총 가격 : reduce()로 가격 합계 계산 (0은 시작 값)
  const totalPrice = products.reduce((sum, product) => sum + product.price, 0);

  // 평균 가격 : 상품이 없으면 0으로 나누지 않도록 0을 돌려줌
  const avgPrice = products.length > 0 ? Math.round(totalPrice / products.length) : 0;

  // 최근 등록 상품 5개 : id가 클수록 나중에 등록한 상품 (b - a : 내림차순)
  // [...products]로 복사한 뒤 정렬해야 원래 상품 목록(상태)이 바뀌지 않음
  const recentProducts = [...products]
    .sort((a, b) => b.id - a.id)
    .slice(0, 5);

  return (
    <div className="admin-page">
      <div className="admin-header">
        <h2>관리자 대시보드</h2>
        {/* 빠른 메뉴 */}
        <div className="admin-menu">
          <Link to='/product/new' className="admin-btn admin-btn_primary">상품 등록</Link>
          <Link to='/' className="admin-btn">상품 목록</Link>
        </div>
      </div>
      {/* 요약 카드 */}
      <div className="admin-cards">
        <div className="admin-card">
          <p>전체 상품</p>
          <strong>{products.length}개</strong>
        </div>
        <div className="admin-card">
          <p>전체 회원</p>
          <strong>{users.length}명</strong>
        </div>
        <div className="admin-card">
          <p>관리자</p>
          <strong>{adminCount}명</strong>
        </div>
        <div className="admin-card">
          <p>평균 상품 가격</p>
          <strong>{avgPrice.toLocaleString()}원</strong>
        </div>
      </div>

      <h3>최근 등록 상품</h3>
      <div className="admin-table-wrap">
        <table>
          <thead>
            <tr>
              <th>번호</th>
              <th>상품명</th>
              <th>카테고리</th>
              <th className="admin-num">가격</th>
            </tr>
          </thead>
          <tbody>
            {recentProducts.map(product => (
              <tr key={product.id}>
                <td>{product.id}</td>
                <td>{product.pName}</td>
                <td>{product.category}</td>
                <td className="admin-num">{product.price.toLocaleString()}원</td>
              </tr>
            ))}
          </tbody>
        </table>
      </div>

      <h3>회원 목록</h3>
      <div className="admin-table-wrap">
        <table>
          <thead>
            <tr>
              <th>번호</th>
              <th>아이디</th>
              <th>이름</th>
              <th>이메일</th>
              <th>권한</th>
            </tr>
          </thead>
          <tbody>
            {users.map(user => (
              <tr key={user.id}>
                <td>{user.id}</td>
                <td>{user.username}</td>
                <td>{user.name}</td>
                <td>{user.email}</td>
                <td>
                    {user.role === "admin" ? "관리자" : "일반회원"}
                </td>
              </tr>
            ))}
          </tbody>
        </table>
      </div>
    </div>
  );
}

export default AdminPage;
  • 권한 검사: 메뉴를 숨겨도 주소창에 /admin을 직접 입력하면 들어올 수 있습니다. 그래서 화면 안에서도 role을 한 번 더 확인하고, 관리자가 아니면 안내 문구만 보여 줍니다.
  • 관리자 수: filter()로 role이 "admin"인 회원만 골라 length로 셉니다.
  • 평균 가격: reduce()로 가격을 모두 더한 뒤 상품 수로 나눕니다. 상품이 0개면 0으로 나누지 않도록 0을 돌려줍니다.
  • 최근 등록 상품: 상품 번호(id)는 Date.now()로 붙이므로 클수록 나중에 등록한 상품입니다. sort((a, b) => b.id - a.id)로 내림차순 정렬한 뒤 slice(0, 5)로 5개만 남깁니다.
  • [...products]로 복사한 뒤 정렬합니다. sort()는 원래 배열을 바꾸므로, 그대로 쓰면 Context의 상품 목록(상태)이 바뀌어 버립니다.
  • 회원 목록에는 비밀번호를 보여 주지 않습니다.

📖 생각해 볼 점 — 화면에서만 막는 권한

지금은 화면(React)에서만 권한을 검사합니다. 브라우저 코드는 누구나 볼 수 있고 고칠 수 있으므로, 실제 서비스에서는 서버가 요청마다 관리자인지 확인해야 합니다. 상품 등록 화면(/product/new)도 지금은 주소를 직접 입력하면 들어갈 수 있으니, AdminPage처럼 화면 안에서 권한을 한 번 더 검사해 보세요.

📖 정리

  1. 권한(role)에 따라 메뉴는 조건부 렌더링으로 보여 주거나 숨긴다.
  2. 메뉴를 숨겨도 주소로 들어올 수 있으므로 화면 안에서도 권한을 검사한다.
  3. 통계는 상태로 따로 두지 않고 filter · reduce로 그때그때 계산한다.
  4. sort()는 원래 배열을 바꾸므로 복사본([...배열])을 정렬한다.

💡 주의 — 새로고침하면 404가 나올 때 React Router는 브라우저 안에서 주소를 바꾸기 때문에, /cart 같은 주소에서 새로고침하면 Render가 그 파일을 찾지 못해 404(Not Found)가 납니다. 배포한 사이트의 Redirects/Rewrites 메뉴에서 Source: /*, Destination: /index.html, Action: Rewrite를 추가하면 모든 주소를 index.html로 보내 React Router가 화면을 그립니다.

📖 생각해 볼 점 — 배포해도 데이터는 브라우저에만

지금 상품 · 회원 · 장바구니는 모두 브라우저 메모리(useState)에 있으므로, 배포한 사이트에서도 새로고침하면 처음 상태로 돌아갑니다. 여러 사람이 같은 데이터를 쓰려면 서버와 DB가 필요합니다. 다음 강의(11강)에서 Express + PostgreSQL 서버와 연결합니다.

📖 정리

  1. npm run build로 배포용 파일을 dist에 만든다. 타입 오류가 있으면 빌드가 실패한다.
  2. 코드는 깃허브에 올리고, Render가 저장소를 받아 설치 · 빌드 · 배포를 대신한다.
  3. Static Site 설정의 핵심은 Root Directory · Build Command · Publish Directory 세 가지다.
  4. React Router를 쓰면 Rewrite(/* → /index.html)를 추가해 새로고침 404를 막는다.

11 상품 이미지 추가

🎯 학습목표
  • 이미지 파일을 public 폴더에 두고 경로로 불러올 수 있다.
  • 선택 속성(?)으로 기존 코드를 깨지 않고 타입에 속성을 추가할 수 있다.
  • ??로 이미지가 없는 상품에 기본 이미지를 보여 줄 수 있다.
  • aspect-ratio와 object-fit으로 크기가 다른 이미지를 같은 크기로 맞출 수 있다.
  • 상품 상세 화면에도 같은 방법으로 이미지를 보여 줄 수 있다.

📖 이미지 파일은 어디에 둘까?

위치쓰는 방법언제 쓰나
public/images/src="/images/mouse.png"처럼 문자열 경로상품처럼 데이터에 경로를 적어 두는 이미지
src/assets/import logo from "./assets/logo.png"로고처럼 코드에 고정된 이미지

상품 이미지는 상품마다 다르고, 나중에 서버(DB)에서 경로를 받아 올 수도 있으므로 public 폴더에 두고 경로(문자열)로 씁니다. public 안의 파일은 빌드할 때 dist로 그대로 복사되어, 배포한 사이트에서도 같은 경로로 열립니다.

💡 예제 — ① 이미지 파일 준비
폴더 구조
shop-mall/ ├─ public/ │ └─ images/ │ ├─ mouse.png │ ├─ keyboard.png │ ├─ monitor.png │ ├─ usb-hub.png │ ├─ webcam.png │ └─ no-image.png ← 이미지가 없는 상품용 └─ src/
  • public 폴더 안에 images 폴더를 만들고 상품 이미지를 넣습니다. 파일 이름은 영문 소문자 · 숫자 · -로 짓습니다.
  • public/images/mouse.png는 브라우저에서 /images/mouse.png로 열립니다. 경로에 public은 적지 않습니다.
  • no-image.png는 이미지가 없는 상품(상품 등록으로 추가한 상품 등)에 보여 줄 기본 이미지입니다.
💡 예제 — ② 상품 타입에 이미지 추가
src/types/product.ts 
// 카테고리 타입 정의
export type Category = "마우스" | "키보드" | "모니터" | "주변기기";

// 상품 타입 정의
export interface Product {
  id: number;
  pName: string;
  category: Category;
  price: number;
  description: string;
  image?: string;  // 상품 이미지 경로 (없을 수도 있으므로 ? 선택 속성)
}

// 상품 등록 시 입력받는 값
// id는 자동으로 부여되므로 제외
export type NewProduct = Omit<Product, "id">;

// 상품 등록 폼 입력값 타입
export interface ProductForm{
    pName: string,
    category: Category,
    price: number,
    description: string
}
  • image?: string의 ?는 선택 속성입니다. 값이 있으면 string, 없으면 undefined입니다.
  • ? 없이 image: string으로 쓰면 이미지가 없는 상품을 만들 수 없어서, 상품 등록(AddProduct)에서 타입 오류가 납니다. 선택 속성으로 두면 기존 코드를 고치지 않아도 됩니다.
  • NewProduct = Omit<Product, "id">는 Product에서 만들어지므로 image?도 자동으로 들어갑니다. 등록 폼 타입(ProductForm)은 그대로 둡니다.

  • alt에는 상품명을 넣습니다. 이미지를 불러오지 못했을 때 대신 보이고, 화면 낭독기가 읽어 주는 글자입니다.
  • 이미지를 Link로 감싸서 상품명처럼 이미지를 눌러도 상세 페이지로 이동합니다.
  • ProductList는 고치지 않습니다. product 객체를 그대로 넘기고 있어서 image도 함께 전달됩니다.

  • width: 100% — 카드 너비에 맞춰 이미지가 늘어나고 줄어듭니다.
  • aspect-ratio: 4 / 3 — 원본 크기가 달라도 이미지 칸의 비율이 같아서 카드 높이가 나란히 맞습니다.
  • display: block — 이미지 아래에 생기는 작은 빈틈(글자 기준선 여백)을 없앱니다.
object-fit 값동작
contain비율을 유지하고 전부 보이게 맞춤. 남는 곳은 빈 곳(카드 배경)으로 보임
cover비율을 유지하고 칸을 꽉 채움. 넘치는 부분은 잘림
fill (기본값)칸에 맞춰 늘리거나 줄임. 비율이 깨져 찌그러질 수 있음

import { Link } from "react-router-dom"
import { useParams } from "react-router-dom"
import { useProduct } from "../context/ProductContext"
import { useCart } from "../context/CartContext"

// 이미지가 없는 상품에 보여 줄 기본 이미지
const NO_IMAGE = "/images/no-image.png";

const ProductDetail = () => {
  const {id} = useParams<{id: string}>()
  const {products} = useProduct();

  }

  return (
    <article className="product-detail">

      <img
        className="product-detail_img"
        src={product.image ?? NO_IMAGE}
        alt={product.pName}
      />
      <span className="product-detail_category">{product.category}</span>
      <h2>{product.pName}</h2>
      <p className="product-detail_price">{product.price.toLocaleString()}원</p>

        className="product-detail_cart"
        onClick={() => {

      >
        장바구니

}

📖 생각해 볼 점 — 새로 등록한 상품의 이미지

상품 등록 화면에는 이미지 입력이 없으므로 새로 등록한 상품은 image가 없고, 카드에 기본 이미지가 나옵니다. 사용자가 올린 이미지를 저장하려면 파일을 받아 보관할 서버가 필요합니다. 11강에서 Express 서버와 DB를 붙인 뒤, DB에 이미지 경로를 저장하는 방식으로 넓힐 수 있습니다.

📖 정리

  1. 상품 이미지는 public/images/에 두고 /images/파일명 경로로 쓴다. 경로에 public은 적지 않는다.
  2. 타입에 속성을 더할 때 선택 속성(?)으로 두면 기존 코드를 고치지 않아도 된다.
  3. 값 ?? 기본값으로 이미지가 없는 상품에 기본 이미지를 보여 준다.
  4. aspect-ratio로 칸의 비율을, object-fit으로 이미지를 칸에 맞추는 방식을 정한다.
